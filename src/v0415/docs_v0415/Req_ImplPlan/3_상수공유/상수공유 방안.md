        ▼

### 방안 B: 빌드타임 코드 생성 (X-macro 파싱) ⭐ 권장

**핵심: X-macro 패턴 도입**

    // C20_Action_0415.h
    #define G_C20_CONSUMER_LIST(X) \
        X(PLAY,        0xB0, 0x000001, "PLAY") \
        X(PAUSE,       0xB1, 0x000002, "PAUSE") \
        X(PLAY_PAUSE,  0xCD, 0x000800, "PLAY_PAUSE") \
        /* ... 24개 ... */

    // enum 자동 생성
    enum EN_C20_Consumer_t : uint32_t {
        #define X(name, usage, mask, str) EN_C20_CON_##name = mask,
        G_C20_CONSUMER_LIST(X)
        #undef X
    };

    // 이름 테이블 자동 생성
    static constexpr const char* G_C20_CONSUMER_NAMES[] = {
        #define X(name, usage, mask, str) str,
        G_C20_CONSUMER_LIST(X)
        #undef X

**Python 파서 (`tools_v0415/gen_const_0415.py`)**

    import re

    def parse_xmacro(header_text, macro_name, fields):
        pattern = rf'#define\s+{macro_name}\(X\)(.*?)(?=\n\n|\Z)'
        block = re.search(pattern, header_text, re.DOTALL).group(1)
        entries = re.findall(r'X\(([^)]+)\)', block)
        result = []
        for entry in entries:
            parts = [p.strip() for p in entry.split(',')]
            result.append(dict(zip(fields, parts)))
        return result

    def gen_js(entries, js_const_name):
        lines = [f'const {js_const_name} = {{']
        for e in entries:
            lines.append(f'  {e["name"]}: {{'
                         f'usage: {e["usage"]}, mask: {e["mask"]}, '
                         f'label: "{e["str"]}" }},')
        lines.append('};')
        return '\n'.join(lines)

**적용 대상 (X-macro 도입할 계열):**

| 계열 | 매크로명 | 필드 |
|---|---|---|
| Consumer | `G_C20_CONSUMER_LIST` | name, usage, mask, str |
| Special | `G_C20_SPECIAL_LIST` | name, id, str |
| Action kind | `G_C20_ACTION_KIND_LIST` | name, id, str |
| Trigger | `G_C10_TRIG_LIST` | name, idx, group, locked |
| KB usage | `G_C20_KB_LIST` | name, usage, str |
| Mode | `G_E10_MODE_LIST` | name, idx, led_rgb, str |
| Slot resolver | `G_C10_RESOLVE_LIST` | name, kind, hold |

**장점:**

| 항목 | 평가 |
|---|---|
| SSOT | ✅ C++ 헤더가 유일 소스 |
| 오프라인 | ✅ 번들에 포함 |
| 초기 지연 | ✅ 없음 (0ms) |
| 컴파일 타임 안전 | ✅ C++ enum 유지 |
| 힙 사용 | ✅ constexpr, 플래시만 |
| 자동 검증 | ✅ Python이 파싱 실패 시 빌드 중단 |

**단점:**

- Python 파서 유지보수 필요 (헤더 포맷 엄격)
- 생성 파일 커밋 or `.gitignore` 결정 필요
- 최초 도입 시 X-macro 전환 리팩터 (7계열)

**비용:** 약 1.5일 (파서 0.5일 + 7계열 전환 1일)

## 5. 리스크 & 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| Python 파서가 X-macro 오파싱 | 빌드 실패 | 파싱 실패 시 **빌드 중단** (fail-fast) |
| 생성 파일 미커밋 → VCS diff 노이즈 | 리뷰 피로 | `.gitignore` + 빌드 시 자동 생성 |
| 생성 파일 커밋 → 수동 편집 사고 | SSOT 위반 | 헤더 상단 "AUTO-GENERATED, DO NOT EDIT" |
| 스펙 문서와 X-macro 이중화 | 문서 노후화 | 스펙 §부록을 "생성 파일 링크"로 축소 |
| Windows CP949 인코딩 | 빌드 오류 | `pio_gzip_0415.py` 기존 정책 준수 (ASCII 로그) |
| C++ 컴파일 시간 증가 | 개발 속도 | X-macro는 컴파일 타임만, 런타임 영향 0 |
| 오프라인 시뮬레이터 스키마 v6와 충돌 | 마이그레이션 | `G_CONST` 참조로 전환, 스키마 버전 유지 |

## 6. 대안 검토 — "API만으로 충분하지 않나?"

**질문:** `/api/keycodes`가 이미 있으니, 프론트가 부팅 시 fetch하면 되지 않나?

**답:** 다음 3가지 이유로 부족합니다.

1. **오프라인 시뮬레이터** — `am_offline_0415.js`는 서버 없이 동작해야 함 (스키마 v6 로컬 저장). API 의존 시 오프라인 완전 붕괴.
2. **초기 로드 순서** — HTML 파싱 → JS 로드 → fetch → 렌더 순서에서 **초기 UI가 상수 없이 그려짐**. 슬롯 드롭다운이 비어 보이는 깜빡임.
3. **힙 절약** — `/api/keycodes`는 이미 "힙 90% 절감" 개선 이력. 부팅마다 큰 JSON을 파싱하면 그 개선이 무효화.

**결론:** API는 **버전 검증용 보조**로만. 주 경로는 **생성 파일**.
