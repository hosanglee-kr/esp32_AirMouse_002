# [v0415] Multi-Host 전환 기능 핵심 구현 방안 및 기본 설계서

> **문서 ID:** PLAN_0415_HostSwitch_v1  
> **기준 문서:** `0415_변경_003.md` (SSOT)  
> **목적:** 리스크와 불필요한 복잡도를 배제하고, 실사용에 가장 안전하고 확실한 Multi-Host 지정 전환 기능의 기본 설계 및 구현 방안 수립  

---

## 1. 개요 및 설계 방향

본 설계는 `0415_변경_003.md`의 Option A(Reject-Until-Target)를 기반으로 하되, **"안전성", "단순성", "실현 가능성"**을 최우선으로 합니다.
- **실패율이 높거나 검증되지 않은 기법 과감히 배제**
- **기존 5대 계약(`CONTRACT`, `STATE`, `FLOW`, `BUDGET`, `SPEC`)의 100% 무결성 유지**
- **사용자 관점에서 직관적이고 오류 없는 전환 경험 제공**

---

## 2. 제외 및 단순화 항목 (고위험·불필요 복잡도 제거)

기술적으로 복잡도가 지나치게 높거나, BLE 스택 안정성을 해칠 수 있는 항목들은 본 구현 범위에서 과감히 제외했습니다.

| 제외 항목 | 제외 사유 및 잠재 리스크 | 대체 방안 (안전한 구현) |
|---|---|---|
| **1. 런타임 GATT 장치명 읽기 (`0x2A00` Read)** | Server 측에서 Client의 GATT를 읽는 동작은 비표준적이며, 연결 직후 수십 ms 블로킹 유발 및 페어링 직후 실패율이 매우 높음. | 웹 UI에서 사용자가 직접 라벨을 지정하는 **수동 라벨링(`hosts_0415.json`)** 및 기본 MAC 주소 노출로 100% 안전하게 대체. |
| **2. LG TV 장치명 스푸핑 (`HOST_TV_NAME_SPOOF`)** | 임의의 상표명(LG/Apple 등) 도용으로 인한 법적/인증 리스크 및 펌웨어 코드 오염. | 순수 표준 HID 규격 준수 및 필요 시 웹 UI 수동 재페어링 버튼 제공. |
| **3. 복잡한 Chorded Select (버튼 컬러 순환)** | 2초 Hold 진입 후 LED 색상 확인 후 다시 클릭하는 제스처는 기존 버튼 FSM(더블클릭, 롱클릭)과 타이밍 충돌 위험이 큼. | **프로파일 슬롯에 호스트 직접 선택 Action 매핑** 또는 **단순 버튼 순환**으로 직관적 처리. |
| **4. 기기별 거절 사유 분기 (0x13 vs 0x16)** | TV 대상 0x13 전송 시 "상대방 사용자가 끊음"이라는 거짓 시맨틱으로 OS 재연결 루프 왜곡 우려. | 블루투스 표준 규격에 부합하는 **`0x16 (Connection Terminated By Local Host)` 단일화**. |
| **5. Directed Advertising / HW 화이트리스트** | ESP32 NimBLE 2.5.1 제약 및 iOS/macOS RPA(주기적 MAC 변경) 환경에서 작동 불가. | 소프트웨어 레벨의 **Reject-Until-Target**으로 안전하게 처리. |

## 3. 핵심 확정 기능 범위 (Minimal Viable Scope)

1. **호스트 정보 영구 저장 (`hosts_0415.json`)**:
   - 최대 3대의 본딩된 호스트 정보(MAC 주소, 사용자 라벨, 고유 색상, 표시 순서) 관리.
   - 기존 검증된 3-Tier Atomic Rotation(`.tmp` → 원본 → `.old`) 적용으로 파일 손상 방지.
2. **Reject-Until-Target BLE 엔진 (B20)**:
   - 지정 전환 시작 시 기존 연결 안전 해제 ➔ 80ms Settle ➔ 재광고 시작.
   - 비대상 호스트가 먼저 접속하면 `0x16` 코드로 즉시 거절 (콜백 내 6바이트 MAC 메모리 비교).
   - 목표 호스트 접속 시 수락 및 정상 세션 유지.
   - 10초 하드 타임아웃 적용 (무한 루프 방지).
3. **5가지 Special Action 확장 (C20/E10)**:
   - `HOST_SELECT_0` (1번 기기 직접 전환)
   - `HOST_SELECT_1` (2번 기기 직접 전환)
   - `HOST_SELECT_2` (3번 기기 직접 전환)
   - `HOST_CANCEL` (전환 시도 즉시 중단)
   - `HOST_TOGGLE` (최근 2개 기기 간 빠른 맞교환)
4. **웹 제어 패널 및 핵심 API 4종 (W10 & UI)**:
   - 9번째 웹 모듈 `am_host_0415.js`를 통해 3대 호스트 상태 카드 제공.
   - 호스트 이름/색상 편집, 클릭 한 번으로 지정 전환, 실시간 연결 상태 토스트 표시.

## 4. 모듈별 기본 설계

### 4.1 B20 BLE Manager (`B20_Ble_0415`)
- **광고 모드 상태 통합:**
  ```cpp
  enum EN_B20_AdvMode_t : uint8_t {
      EN_B20_ADV_IDLE   = 0,  // 일반 대기/접속 상태
      EN_B20_ADV_CYCLE  = 1,  // 단순 순환 모드
      EN_B20_ADV_TARGET = 2   // 특정 호스트 강제 전환 모드
  };
  ```
- **RPA 자동 활성화:**
  - `NimBLEDevice::setOwnAddrType(BLE_OWN_ADDR_RPA_RANDOM_DEFAULT)`를 호출하여 내부에서 `ble_hs_pvcy_rpa_config(1)`가 자동 실행되도록 설정 (iOS/macOS 완벽 대응).
- **타겟 비교 로직:**
  - `NimBLEAddress::equals()`의 타입 불일치 버그를 회피하기 위해 `memcmp(connIdAddr.getVal(), targetAddr.getVal(), 6) == 0` 사용.

### 4.2 C10 Config Manager (`C10_Config_0415`)
- **저장 파일:** `/json/hosts_0415.json`
  ```json
  {
    "ver": 1,
    "hosts": [
      {"addr": "AA:BB:CC:DD:EE:01", "label": "내 노트북", "color": "#00A0FF", "order": 0},
      {"addr": "AA:BB:CC:DD:EE:02", "label": "아이패드",   "color": "#FFA500", "order": 1},
      {"addr": "AA:BB:CC:DD:EE:03", "label": "거실 TV",    "color": "#00FF40", "order": 2}
    ]
  }
  ```
- **NVS 본딩 자동 정합:**
  - 4번째 기기가 페어링되어 NimBLE NVS FIFO에서 가장 오래된 기기가 자동 삭제되면, `hosts_0415.json`에서도 해당 MAC 주소를 자동 정리.

### 4.3 E10 & C20 Task/Action 연동 (CONTRACT §3 준수)
- **신규 큐 미생성 원칙 준수:**
  - Web API에서 호스트 전환 요청 시 큐를 생성하지 않고 단일 원자적 변수 `g_reqHostOp`에 요청 기록.
  - `sensorTask` (8ms 루프) 시작점에서 이 변수를 안전하게 소비하여 B20 동기 호출 실행.
- **절전 모드 간섭 방지 (Sleep Gate):**
  - 전환 중(`_advMode == EN_B20_ADV_TARGET`)에는 마우스가 멈춰 있어도 Light-Sleep 진입을 일시 유예(`isSelecting()`).

### 4.4 W10 Web API 및 UI 모듈
- **REST API 4종:**
  - `GET /api/hosts`: 호스트 목록 및 현재 활성 기기 조회
  - `POST /api/hosts/select`: 지정 호스트 전환 요청 (`{"idx": 1}`)
  - `POST /api/hosts/cancel`: 전환 취소
  - `POST /api/hosts/label`: 사용자 라벨 및 표시 색상 저장
- **프론트엔드 모듈:** `am_host_0415.js` (9번째 모듈로 정식 통합)

## 5. 🤔 핵심 의사결정 필요 항목 (작동 예시 및 선택)

구현 착수 전 사용자 관점에서 동작 방식을 확정해야 하는 **3가지 핵심 의사결정 항목**입니다.

---

### [의사결정 1] 목표 호스트 연결 실패 시 폴백(Fallback) 동작 방식
👉 **[확정] 옵션 B — 연결 시도 즉시 중단 (Strict / Stop)**
- **동작 방식:** 목표 호스트 전환 시도 후 10초 타임아웃 발생 시, 다른 기기로 임의 연결하지 않고 **LED 적색 3회 점멸 후 대기 상태(IDLE)로 즉시 중단**.
- **확정 사유:** 사용자가 지정한 목표 기기 외에 다른 원치 않는 기기가 자동으로 붙는 것을 엄격하게 차단하고, 사용자의 명시적 조작 의도를 100% 존중.

---

### [의사결정 2] 물리 버튼을 통한 호스트 전환 조작 방식
👉 **[확정] 옵션 C — Side C 순환 + 프로파일 슬롯 직접 선택 모두 지원**
- **동작 방식:**
  1. **기본 순환 (Host Cycle 업그레이드):** Side C 3초 Hold 시, 기존 단순 Disconnect 대신 **[0번] ➔ [1번] ➔ [2번] 순서로 목표 호스트를 강제 순환 지정 전환**.
  2. **슬롯 직접 매핑 (Special Action 5종):** 프로파일 슬롯 드롭다운에 `HOST_SELECT_0`, `HOST_SELECT_1`, `HOST_SELECT_2`, `HOST_TOGGLE`, `HOST_CANCEL` 액션을 개방하여 원하는 버튼 제스처(예: Top L/R 더블클릭)로 1-Click 다이렉트 전환 지원.
- **확정 사유:** 버튼 슬롯을 아끼고 싶은 경우 Side C 하나로 순환 전환하고, 특정 기기로 즉시 가고 싶을 때는 단축 버튼을 지정할 수 있는 최고의 유연성 확보.

---

### [의사결정 3] 에어마우스 전원을 켰을 때(부팅 시) 첫 연결 우선순위
👉 **[확정] 옵션 A — 마지막 사용 기기 우선 연결 (Last Host Memory)**
- **동작 방식:**
  - 마우스 연결 중이던 호스트 주소를 `boot_state_0415.json`의 `last_host_addr`에 지속 기억.
  - 전원 스위치를 켰을 때(부팅 직후), `last_host_addr` 기기를 타깃으로 지정하여 **10초간 우선 연결 시도 (`EN_B20_ADV_TARGET`)**.
  - 만약 해당 기기가 켜져 있지 않아 타임아웃이 나면 대기 모드로 안전 전환.
- **확정 사유:** 전원을 켤 때마다 주변의 다른 기기(스마트폰 등)로 엉뚱하게 연결이 튀는 현상을 방지하고, 직전에 작업하던 기기 환경을 그대로 유지.

## 6. 단계별 개발 절차 (Phase 1 ~ Phase 4)

확정된 의사결정(1-B, 2-C, 3-A)을 바탕으로 아래 로드맵에 따라 개발을 진행합니다.

1. **Phase 1 (기반 인프라 - C10 & B20 기초)**:
   - `C10_Def_0415.h`에 `ST_C10_Host_t`, `ST_C10_HostsConfig_t` 정의.
   - `C10_Config_0415.cpp`에 Atomic Rotate 기반 `loadHosts()`, `saveHosts()`, `boot_state` 확장 구현.
   - `B20_Ble_0415.cpp`에 `NimBLEDevice::setOwnAddrType(BLE_OWN_ADDR_RPA_RANDOM_DEFAULT)` 적용.
2. **Phase 2 (B20 Reject 엔진 & 순환 로직)**:
   - `EN_B20_AdvMode_t` (`IDLE`, `CYCLE`, `TARGET`), 80ms Settle, `isSameBleAddress()` 6바이트 MAC 비교 콜백 구현.
   - Strict 모드(타임아웃 시 중단) 및 Side C 3초 Hold의 강제 순환(`cycleActivePeer()`) 구현.
   - `sensorTask` Sleep Gate 연동.
3. **Phase 3 (Special Action & E10 sensorTask 위임)**:
   - `HOST_SELECT_0~2`, `TOGGLE`, `CANCEL` 5종 구현 및 `g_reqHostOp` 단일 플래그 비동기 소비 루틴 구현.
4. **Phase 4 (W10 Web API & am_host_0415.js 웹 UI)**:
   - `/api/hosts` 4종 API 구현, 웹 호스트 관리 카드 및 슬롯 Special 드롭다운 라벨 연동.
