NimBLE 2.5.1 API에서 `NimBLEConnInfo` 에 `getName` 이 없음. NimBLE-Arduino 2.x API에서 peer 이름을 얻는 방법을 확인해야 함.

NimBLE-Arduino 2.x의 `NimBLEConnInfo` 클래스는:

- `getAddress()` (NimBLEAddress)
- `getConnHandle()` / `getConnId()`
- `isConnected()`
- `getMTU()`
- `isEncrypted()`
- `isAuthenticated()`
- `isBonded()`
- `getIdAddress()`
- `getAddressType()`

`getName` 은 없음.

NimBLE-Arduino 2.x에서 peer의 device name을 얻으려면:

1. `NimBLEDevice::getServer()->getPeerInfo(connId)` → NimBLEConnInfo
2. NimBLEClient도 아니고 server 쪽 peer의 이름은 GATT characteristic (0x2A00 Device Name)을 read하거나, bond 정보에서 가져와야 함.

간단한 방법:

- `NimBLEDevice::getServer()->getPeerIDInfo()` — 없을 수 있음
- `NimBLEDevice::getServer()->getPeerName(connId)` — NimBLE-Arduino 2.x에 이런 메서드가 있는지?

실제로 NimBLE-Arduino 2.x에서 `NimBLEServer` 에는 peer 이름 접근 API가 직접 없음. 대신:

1. **NimBLEDevice::getBondedDevices()** → 벡터의 각 NimBLEAddress에 대해
2. **getPeerInfo(connId).getAddress()** 로 MAC만 얻기
3. Device Name은 **peer의 GATT characteristic을 read** 해야 함

간단하게 MAC 주소만 노출하는 것이 실용적.

## 향후 개선 (선택, v0416 후보)

Peer **Device Name** 을 표시하려면:

1. `NimBLEServerCallbacks::onConnect(NimBLEServer*, NimBLEConnInfo&)` 에서 `NimBLEAddress` 캡처
2. 최초 연결 시점에 peer GATT characteristic `0x2A00` (Device Name) read
3. 캡처한 이름을 `_peerNameCache[connId]` 에 저장
4. `getPeerName()` 이 캐시된 이름 반환

**비용**:

- GATT read는 최초 1회 (연결 직후) → 수십 ms
- 캐시 해제는 disconnect 시
- 콜백 의존성 증가 → 복잡도 상승

## 🔴 Critical — 즉시 수정 필요 (6건)

### C-1. NimBLE 2.5.1 콜백 시그니처 오류 (§2.2)

**설계서**:

```
void onConnect(NimBLEServer*, ble_gap_conn_desc* desc) {
    if (_rejectMode && !_isTargetAddr(desc->peer_id_addr)) {
        NimBLEDevice::getServer()->disconnect(desc->conn_handle, v_reason);
```

**실제 NimBLE-Arduino 2.5.x**:

```
virtual void onConnect(NimBLEServer* pServer, NimBLEConnInfo& connInfo);
```

- `ble_gap_conn_desc*` 는 **NimBLE-Arduino 1.4.x 이하** 시그니처
- 최근 컴파일 에러(`getName()` 없음)에서 확인된 대로 v2.5.1은 `NimBLEConnInfo&` 사용

**수정**:

```
void CL_B20_Ble::onConnect(NimBLEServer* p_srv, NimBLEConnInfo& p_info) {
    if (_rejectMode) {
        NimBLEAddress v_peer(p_info.getAddress());
        if (!_isTargetAddr(v_peer)) {
            uint8_t v_reason = _isTvTarget() ? 0x13 : 0x16;
            p_srv->disconnect(p_info.getConnHandle(), v_reason);
            return;
        }
        _rejectMode = false;
    }
    _onConnected(p_info);
}
```

### C-2. NimBLEDevice::getBondedDevices() 미존재 (§2.2)

**설계서**: `auto bonds = NimBLEDevice::getBondedDevices();`

**실제 v2.5.1**: `getBondedDevices()` 는 존재하나 **`std::vector<NimBLEAddress>` 반환** 이 아니라 서버 스코프에서만 접근. 공식 문서 확인 필요.

**대안 (검증된 API)**:

```
bool CL_B20_Ble::_isTargetAddr(const NimBLEAddress& p_addr) const {
    // [v0415 Option A] NVS FIFO 기반 본딩 조회
    //   - NimBLEDevice::getNumBonds() / getBondedAddress(idx)
    //   - Identity Address 기준 비교 (RPA 해결 후)
    const int v_n = NimBLEDevice::getNumBonds();
    for (int i = 0; i < v_n; i++) {
        NimBLEAddress v_bond = NimBLEDevice::getBondedAddress(i);
        if (v_bond.equals(p_addr)) return true;
    }
    return false;
}
```

**주의**: `getBondedAddress()` 도 v2.5.1 실제 노출 여부 컴파일 검증 필수.

### C-3. setOwnAddrType() 인자 개수 (§5.3)

**설계서**: `setOwnAddrType(BLE_OWN_ADDR_RANDOM, false)`

**실제**: NimBLE-Arduino 2.5.1은 **1-arg** `setOwnAddrType(uint8_t)`. 2-arg는 존재하지 않음.

**수정**:

```
NimBLEDevice::setOwnAddrType(BLE_OWN_ADDR_RANDOM);
// RPA 활성화는 별도: ble_hs_pvcy_rpa_config(1)
```

### C-4. ble\_hs\_pvcy\_rpa\_config(1) 직접 호출 위치 (§5.3)

**문제**: 이 함수는 NimBLE-Arduino wrapper가 아닌 **NimBLE stack 내부 API**. 호출 시점이 잘못되면 abort 발생.

**정확한 시점**:

```
// main.cpp 또는 B20::begin()에서
// 1) NimBLEDevice::init() 완료
// 2) onSync 콜백 대기 (NimBLEDevice::getSynced() == true)
// 3) 그 이후 ble_hs_pvcy_rpa_config(1) 호출
```

**컴파일 검증**: `extern "C" int ble_hs_pvcy_rpa_config(uint8_t);` include 필요 (`host/ble_hs.h`).

### C-5. \_qHostCmd 신규 큐 — 기존 CONTRACT §3 위반 (§5.1)

**설계서**: `_qHostCmd (신규 큐)` 도입 제안

**CONTRACT\_0415.md §3**: 큐는 **3개로 고정** (`_qFrame`, `_qActionExec`, `_qHidCmd`). 신규 큐 추가는 스펙 위반.

**해결**: 기존 **async 위임 플래그 패턴** 재사용

```
// E10_AirMouse_0415.h에 추가
volatile uint8_t _reqHostSelect = 0xFF;  // 0xFF = none
volatile bool    _reqHostCancel = false;
volatile bool    _reqHostRepair = false;

// W10 → E10 → sensorTask → B20 (기존 _reqSpecialAction과 동일 경로)
```

**§2.7 위임 플래그 목록** 에 3개 추가하면 신규 큐 불필요.

### C-6. host\_select\_policy 스키마 위치 (§7.1, §7.3)

**설계서**: `e10.power.host_select_policy` / `host_select_timeout_ms`

**문제**: **프로파일과 host 본딩이 분리된 개념**. 정책이 프로파일에 있으면 프로파일 전환 시 정책이 바뀌어 **일관성 붕괴**.

**수정 제안**:

```
// hosts_0415.json에 최상위로 이동
{
  "ver": 1,
  "policy": "fallback_last",
  "timeout_ms": 10000,
  "hosts": [ ... ]
}
```

**또는** `e10` 하위 별도 섹션:

```
"e10": {
  "host_select": {
    "policy": "fallback_last",
    "timeout_ms": 10000
  }
}
```

**문제**:

- ESP32 부팅 → select 시작 → target 미접속 상태면 **10초 타임아웃 대기**
- 이 동안 다른 호스트(예: 노트북) 접속 시도 → 모두 reject
- 사용자 체감: "노트북 연결이 안 됨"

**개선**:

```
// 부팅 시나리오
if (last_host_addr != "") {

    // 옵션 B: N초 지연 후에만 시도 (사용자가 먼저 조작 가능)
    _scheduleReconnect(last_host_addr, /*delayMs=*/3000);
}
```

### M-4. GATT Device Name 캐싱 (§6.3 P2-6)의 복잡도

**문제**:

- Windows는 CCCD 이슈로 read 실패 가능
- 이름 없는 기기(TV) 다수

**판단**: P2 유지 + **실패 시 수동 라벨 폴백** 을 P0로 명시 강화 권장

**중요**: 기존 ESP32-BLE-CompositeHID가 내부 콜백 소유 → **덮어쓰기 대신 래핑** 필요.

```
// B20_Ble_0415.cpp
class CL_B20_ServerCallbacks : public NimBLEServerCallbacks {
    CL_B20_Ble* _owner;
public:
    CL_B20_ServerCallbacks(CL_B20_Ble* p) : _owner(p) {}

    void onConnect(NimBLEServer* p_srv, NimBLEConnInfo& p_info) override {
        if (_owner->_rejectMode) {
            NimBLEAddress v_peer(p_info.getAddress());
            if (!_owner->_isTargetAddr(v_peer)) {
                uint8_t v_reason = _owner->_getRejectSettleMs() >= 150 ? 0x13 : 0x16;
                p_srv->disconnect(p_info.getConnHandle(), v_reason);
                D10_LOGI("[B20] reject non-target peer");
                return;
            }
            _owner->_rejectMode = false;
            D10_LOGI("[B20] target peer accepted");
        }
    }
};
```

**⚠️ 검증 필요**: ESP32-BLE-CompositeHID가 자체 콜백 setter 제공 여부.

- **불가** 시: B20이 CompositeHID 대신 자체 서버 콜백 관리 → 대규모 리팩터
- **가능** 시: `setServerCallbacks()` 경유

**대안 (안전)**: CompositeHID의 **연결 이벤트 훅이 없으면** 주기 polling으로 비대상 connId 감지 → 즉시 `disconnect()` 호출 (10~50ms 지연 허용).
