🔴 Critical — 마우스 stuck 위험

BB-1. MOUSE_HOLD 슬롯을 CLICK 이벤트에 지정 시 press stuck

재현 경로:

1. Web UI → S6(Top R Click) 슬롯에 MOUSE_HOLD 지정
2. Top R 클릭
3. 백엔드: CLICK 이벤트만 발화 → _enqueueAction(MOUSE_HOLD, true) 1회만
4. ActionExec::exec(MOUSE_HOLD, true) → _mouse->mousePress(M_R)
5. mouseRelease 호출 없음 → 우클릭 영구 눌림

근본 원인 (E10_AirMouse_Action_0412.cpp):

```cpp
void CL_E10_EliteAirMouse::_handleSlotButton(uint8_t p_btnId, uint8_t p_evt) {
    for (const auto& e : G_SLOT_MAP) {
        if (e.evt != p_evt) continue;

        bool v_isDown = true;
        if (p_evt == EN_C20_EVT_UP) v_isDown = false;  // ← UP 이벤트가 G_SLOT_MAP에 없음 → 항상 true
        (void)_enqueueAction(v_slot, v_isDown);
        return;
    }
}
```

G_SLOT_MAP에는 CLICK/DOUBLE/LONG만 있어 DOWN/UP은 이 경로로 오지 않음. 즉 MOUSE_HOLD 슬롯은 CLICK 이벤트 시 press만 되고 release 미호출.

SPEC 확인 (00.SPEC_0412_002.md):

· Top L: DOWN → Mouse Hold press, UP → release, CLICK → 스킵(중복 방지)

S1만 하드코딩으로 DOWN/UP 페어 처리. 다른 슬롯의 MOUSE_HOLD는 방어 없음.

영향:

· ActionExec::_execMouseHold의 _allocRuntime으로 런타임 등록됨 → 이후 다른 슬롯 조작 시까지 press 유지
· BLE disconnect까지 stuck

권장 조치 (3가지 옵션):

옵션 조치 장점 단점
A Web UI에서 MOUSE_HOLD를 S1 외 잠금 즉시 방어 유연성 저하
B CLICK 이벤트에서 MOUSE_HOLD 감지 시 tap으로 자동 release 유연성 유지 별도 타이머 필요
C DOWN/UP 이벤트도 슬롯 매핑에 라우팅 완전 지원 대규모 리팩터

권장: B (tap 자동 처리)

수정안 (E10_AirMouse_Action_0412.cpp::_handleSlotButton):

```cpp
if (v_slot.kind == (uint8_t)EN_C20_ACT_MOUSE_HOLD) {
    // [BB-1] CLICK 계열 이벤트에서 MOUSE_HOLD는 tap으로 처리 (press + 지연 release)
    (void)_enqueueAction(v_slot, true);         // press
    // release는 ActionExec이 자체 tap으로 처리하도록 별도 kind 변환 필요
    ST_C20_ActionSlot_t v_tap = v_slot;
    v_tap.kind     = (uint8_t)EN_C20_ACT_MOUSE_CLICK;   // MOUSE_CLICK으로 변환
    v_tap.holdMode = (uint8_t)EN_C20_HOLD_NONE;
    (void)_enqueueAction(v_tap, true);          // click(내부 press-release)
    return;
}
```

더 안전한 방식: Web UI에서 MOUSE_HOLD를 S1 외 lock + 경고 (옵션 A) 병행.

🟠 High — 상태머신 결함

BB-2. Side C 3초 유지 시 HOLD_2S + HOLD_3S 둘 다 발화 → Pairing 후 Host Cycle 진입

코드 (C20_BtnDispatcher_0412.cpp::_checkTimers):

```cpp
if (b.phase == PHASE_PRESSED) {
    const uint32_t v_held = p_now - b.downMs;

    if (!b.longFired && v_held >= _longDelayMs)  { _emit(LONG);    b.longFired   = true; }
    if (!b.hold2sFired && v_held >= _hold2sMs)   { _emit(HOLD_2S); b.hold2sFired = true; }
    if (!b.hold3sFired && v_held >= _hold3sMs)   { _emit(HOLD_3S); b.hold3sFired = true; }
}
```

재현:

1. Side C를 3초 이상 유지
2. t=2000ms: HOLD_2S 발화 → _handleSpecial(PAIRING) → BLE 페어링 진입
3. t=3000ms: HOLD_3S 발화 → _handleSpecial(HOST_CYCLE) → 재광고 + disconnect

사용자 의도: 3초 눌렀으면 Host Cycle만.

SPEC 재확인 (00.SPEC_0412_002.md):

| Side C 3초 + Top L DOWN | Host Cycle (disconnect + 재광고) |

rev6:

· Side C 3초 hold (단독) | Host Cycle (disconnect + 재광고)

"단독"이 명시되어 있으나 dispatcher가 이 조건을 판정하지 않음.

추가 이슈: SPEC rev6의 "3초 + Top L DOWN"과 "3초 단독" 사이에 정책 불일치. 실제 코드는 단독 3초를 가정.

권장 수정 (C20_BtnDispatcher_0412.cpp):

Option 1 — HOLD_2S와 HOLD_3S 배타 처리:

```cpp
if (b.phase == PHASE_PRESSED) {
    const uint32_t v_held = p_now - b.downMs;

    if (!b.longFired && v_held >= _longDelayMs) { _emit(LONG); b.longFired = true; }

    // [BB-2] 2초 hold: 3초 미만일 때만 유효
    //   - 3초 이상 유지 시 HOLD_2S 취소
    if (!b.hold3sFired && v_held >= _hold3sMs) {
        _emit(HOLD_3S);
        b.hold3sFired = true;
        b.hold2sFired = true;   // ★ HOLD_2S 무력화
    } else if (!b.hold2sFired && v_held >= _hold2sMs) {
        _emit(HOLD_2S);
        b.hold2sFired = true;
    }
}
```

Option 2 — 2초 hold 발화를 release 시점까지 지연:

```cpp
// HOLD_2S는 RELEASE 시점에 판정 (3초 미만 + 2초 이상)
// 현재 구조와 다름 → 리팩터 필요
```

권장: Option 1 (변경 최소).

주의: 위 수정은 2초 발화 시점을 3초 이후로 미룸 → 2초에 LED blink 시작 못함. UX 재검토 필요.

대안 (배타 처리 유지하며 2초에 발화):

· HOLD_2S 발화 후 HOLD_3S는 emit 안 함
· 3초 이상 유지 시: HOLD_2S 취소 메커니즘 필요 (SPEC 위반)
· → Pairing 진입 후 Host Cycle 무시

```cpp
if (!b.hold2sFired && !b.hold3sFired && v_held >= _hold2sMs) {
    _emit(HOLD_2S);
    b.hold2sFired = true;
}
// HOLD_3S는 HOLD_2S 발화 후 스킵
if (!b.hold3sFired && !b.hold2sFired && v_held >= _hold3sMs) {
    _emit(HOLD_3S);
    b.hold3sFired = true;
}
```

최종 판단 필요: "2초 Pairing → 3초 Host Cycle"의 의도된 UX를 확정해야 함.

BB-3. resetButton에서 downMs/upMs 미초기화 → Mode 전환 후 잔존 클릭 발화

코드:

```cpp
void CL_C20_BtnDispatcher::resetButton(uint8_t p_btnId) {
    ST_BtnState_t& b = _btn[p_btnId];
    b.phase          = PHASE_IDLE;
    b.longFired      = false;
    b.hold2sFired    = false;
    b.hold3sFired    = false;
    b.lastRawChangeMs = (uint32_t)millis();
    b.stableCount     = 0;
    b.rawDownMs       = 0;
    // ★ downMs, upMs, waitClickStartMs 초기화 안 됨
}
```

재현:

1. Top L을 1초 눌림 (downMs = T0, rawDownMs = T0)
2. Mode 전환 (예: Side C 더블클릭) → _setActiveMode → _btnDisp.resetAll()
3. resetButton(TOP_L) → downMs 유지 (T0), phase = IDLE
4. Top L UP 이벤트 → _onStableChange(UP):
   · v_heldMs = rawDownMs ? (lastRawChangeMs - rawDownMs) : (p_now - downMs)
   · rawDownMs = 0 (reset으로 초기화됨) → p_now - downMs 사용
   · downMs = T0 이므로 1초 이상 → minClickMs 초과
   · PHASE_IDLE이므로 phase 전이 없음?

실제로: reset 후 phase=IDLE이므로 if (b.phase == PHASE_PRESSED) 분기 실행 안됨. CLICK 발화 없음.

BUT: reset 직후 다시 DOWN 발생 시 rawDownMs = p_now, downMs = p_now. 정상.

판정: 실제 재현 안됨. 다만 잠재적 위험. 코드 리뷰 시 명확성 저하.

권장 수정 (선택):

```cpp
void CL_C20_BtnDispatcher::resetButton(uint8_t p_btnId) {
    ST_BtnState_t& b = _btn[p_btnId];
    b.phase            = PHASE_IDLE;
    b.downMs           = 0;    // [BB-3] 추가
    b.upMs             = 0;    // [BB-3] 추가
    b.waitClickStartMs = 0;    // [BB-3] 추가
    b.longFired        = false;
    b.hold2sFired      = false;
    b.hold3sFired      = false;
    b.lastRawChangeMs  = (uint32_t)millis();
    b.stableCount      = 0;
    b.rawDownMs        = 0;
}
```

BB-4. _qActionExec 큐 drop 시 클릭 유실

코드 (E10_AirMouse_Action_0412.cpp::_enqueueAction):

```cpp
bool CL_E10_EliteAirMouse::_enqueueAction(const ST_C20_ActionSlot_t& p_slot, bool p_isDown) {
```

· SPEC 정책상 의도된 drop (커서 지연 방지 우선)
· 실무에서 8개가 full될 일은 드묾
· BUT 매크로 실행 중 UI 반응성 저하 가능

· _qActionExec 크기 확장 (8 → 16)
· 또는 HID RELEASE_ALL 우선순위 큐 별도
· 또는 click 이벤트는 _qHidCmd로 라우팅 (별도 큐 size 4)

우선순위 낮음. 현재 SPEC 유지.

```cpp
// =====================================================
// [버튼 6종] C20_BtnDispatcher::EN_C20_BtnId_t 순서와 1:1
// =====================================================

static constexpr int PIN_BTN_TOP_M  = 16;
static constexpr int PIN_BTN_TOP_R  = 15;
static constexpr int PIN_BTN_SIDE_F = 14;
static constexpr int PIN_BTN_SIDE_C = 13;
static constexpr int PIN_BTN_SIDE_R = 7;

    PIN_BTN_TOP_L,   // EN_C20_BTN_TOP_L
    PIN_BTN_TOP_M,   // EN_C20_BTN_TOP_M
    PIN_BTN_TOP_R,   // EN_C20_BTN_TOP_R
    PIN_BTN_SIDE_F,  // EN_C20_BTN_SIDE_F
    PIN_BTN_SIDE_C,  // EN_C20_BTN_SIDE_C
    PIN_BTN_SIDE_R,  // EN_C20_BTN_SIDE_R
};

// =====================================================
// [I2C]
// =====================================================
static constexpr int PIN_I2C_SDA = 4;
static constexpr int PIN_I2C_SCL = 5;

// =====================================================
// [MPU6050 INT]
// =====================================================
static constexpr int PIN_MPU_INT = 6;

// =====================================================
// [LED]
// =====================================================

// =====================================================

// =====================================================

// =====================================================
// [EXT1 wake mask 빌더] (버튼 + MPU INT)
// =====================================================
static constexpr uint64_t buildWakeMaskAll() {
    uint64_t v = (1ULL << PIN_MPU_INT);
    for (int i = 0; i < 6; i++) v |= (1ULL << BTN_PINS[i]);
    return v;
}

static constexpr uint64_t buildWakeMaskButtons() {
    uint64_t v = 0;
    for (int i = 0; i < 6; i++) v |= (1ULL << BTN_PINS[i]);
    return v;
}
```

```cpp
#pragma once
/*
 * ------------------------------------------------------
 * 소스명 : HW_Def_0412.h
 * 모듈약어 : HW
 * 모듈명 : Hardware Pin Definitions (Single Source of Truth)
 * ------------------------------------------------------
 * 기능 요약
 *  - 모든 GPIO 핀의 단일 정의 위치 (매직넘버 5중복 제거)
 *  - E10(센서/I2C), C20(버튼), P20(전원/WoM), L10(LED)이 참조
 *  - EXT1 wake mask를 constexpr로 자동 계산 (하드코딩 제거)
 *
 * [설계]
 *  - namespace HW_DEF: 모듈약어 접두사 규칙 준수
 *  - 상수 이름은 C20 EN_C20_BtnId_t 순서와 1:1 (TOP_L/TOP_M/TOP_R/SIDE_F/SIDE_C/SIDE_R)
 *  - BTN_PINS[] 배열이 C20_BtnDispatcher::G_PINS와 동일 순서
 *  - buildWakeMaskAll()/buildWakeMaskButtons()로 EXT1 mask 자동 생성
 *
 * [하드웨어 배치]
 *        [Top 면]
 *     [L]   [M]   [R]
 *
 *   ┌─────────────┐
 * [F]│             │
 * [C]│             │  ← 좌측면 (Front/Center/Rear)
 * [R]│             │
 *   └─────────────┘
 * ------------------------------------------------------
 * [구현 규칙]
 *  - 항상 소스 시작 주석 부분 체계 유지 및 내용 업데이트
 *  - 소스 시작 주석 부분 구현규칙, 코드네이밍규칙 내용 그대로 유지, 수정금지
 *  - ArduinoJson v7.x.x 사용 (v6 이하 사용 금지)
 *  - memset + strlcpy 기반 안전 초기화
 * ------------------------------------------------------
 * [코드 네이밍 규칙]
 *   - namespace 명        : 모듈약어_ 접두사
 *   - namespace 내 상수    : 모둘약어 접두시 미사용
 *   - 전역 상수,매크로      : G_모듈약어_ 접두사
 *   - 함수 로컬 변수        : v_ 접두사
 *   - 함수 인자             : p_ 접두사
 * ------------------------------------------------------
 */

#include <Arduino.h>

namespace HW_DEF {

// =====================================================
// [버튼 GPIO] C20_BtnDispatcher::EN_C20_BtnId_t 순서와 1:1
// =====================================================
static constexpr int PIN_BTN_TOP_L  = 12;   // EN_C20_BTN_TOP_L  (좌클릭/Drag)
static constexpr int PIN_BTN_TOP_M  = 16;   // EN_C20_BTN_TOP_M  (Move Gate)
static constexpr int PIN_BTN_TOP_R  = 15;   // EN_C20_BTN_TOP_R  (우클릭)
static constexpr int PIN_BTN_SIDE_F = 14;   // EN_C20_BTN_SIDE_F (Front Hold)
static constexpr int PIN_BTN_SIDE_C = 13;   // EN_C20_BTN_SIDE_C (Mode/Pairing/Host Cycle)
static constexpr int PIN_BTN_SIDE_R = 7;    // EN_C20_BTN_SIDE_R (보조)

static constexpr uint8_t BTN_COUNT = 6;

// C20_BtnDispatcher::G_PINS 순서와 1:1 (EN_C20_BtnId_t 순서)
static constexpr int BTN_PINS[BTN_COUNT] = {
    PIN_BTN_TOP_L,
    PIN_BTN_TOP_M,
    PIN_BTN_TOP_R,
    PIN_BTN_SIDE_F,
    PIN_BTN_SIDE_C,
    PIN_BTN_SIDE_R,
};

// =====================================================
// [I2C 버스]
// =====================================================
static constexpr int PIN_I2C_SDA = 4;
static constexpr int PIN_I2C_SCL = 5;

// =====================================================
// [MPU6050 INT1] WoM wake 소스
// =====================================================
static constexpr int PIN_MPU_INT = 6;

// =====================================================
// [LED] WS2812 단일 LED (DIN)
// =====================================================
static constexpr int PIN_LED_WS2812 = 21;

// =====================================================
// [배터리 ADC] (미구현, 향후)
// =====================================================
static constexpr int PIN_BATT_ADC = 1;

// =====================================================
// [EXT1 wake mask 빌더] (constexpr, 매직넘버 제거)
// -------------------------------------------------------
// ESP32 EXT1 wake는 LOW active, 64-bit mask 사용
//  - buildWakeMaskAll()     : MPU INT + 6버튼 (Light-sleep)
//  - buildWakeMaskButtons() : 6버튼만 (Deep-sleep)
```
