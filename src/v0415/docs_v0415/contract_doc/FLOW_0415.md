> 4. **라벨 내부 화살표 기호 유니코드 치환**: 텍스트 내부의 `->`는 연결선 구문과 혼동되지 않도록 유니코드 화살표 `➔`로 치환합니다.
> 5. **그래프 연결성(Connectivity) 보장**: 모든 노드는 선행 에지와 유기적으로 연결되어야 하며, 선행 연결이 없는 고립 노드(Unrooted/Disconnected Node)를 생성하지 않습니다.

## 1. 모션 처리 파이프라인 (`sensorTask` 내부, 8ms 주기)

```mermaid
    C4 --> D{"Front Hold Side F?"}
    D -- "누름 상태" --> D1["커서 감쇠 scrollCursorDamp + Wheel/Pan"]
    D -- "미누름" --> E{"Move Gate Top M?"}
    D1 --> E
```

## 2. 프로파일 전환 파이프라인 (`switchProfile(idx)`)

웹 태스크 또는 내부 요청에 의해 프로파일을 전환할 때 시스템 안전성을 보장하는 순차 시퀀스입니다.

```mermaid
sequenceDiagram
    participant Web as Web / AsyncServer
    participant Core as E10 Core
    participant Q as FreeRTOS Queues
    participant Sensor as sensorTask
    participant Comm as commTask
    participant FS as LittleFS

    Web->>Core: switchProfile(newIdx)
    Note over Core: 1. 재진입 차단 플래그 검사
    Core->>Core: _lock(), _macroAbortToken++, active=false, _unlock()
    Core->>Q: 큐 드레인 (_qActionExec, _qHidCmd)
    Core->>Sensor: 리셋 위임 플래그 설정 (_reqResetBtnDisp, _reqResetGesture)
    Core->>Comm: 릴리즈 위임 플래그 설정 (_reqCommReleaseAll = true)
    Core->>Q: forceReleaseButtons() ➔ _qHidCmd 인큐
    Core->>FS: setActiveIndex(newIdx) & LittleFS 프로파일 로드
    Core->>Core: _cfgProfile 갱신 & 런타임 캐시 반영
    Core->>Core: _engine.resetEmaState() (v0415)
    Core->>Core: LED 모드 색상 + 화이트 0.5초 Flash
    Core-->>Web: 성공 반환 (true)
    Note over Sensor: 다음 8ms 틱에서 _btnDisp.resetAll(), _gesture.reset() 실행
    Note over Comm: 큐 소비 또는 플래그 확인 시 _actExec.releaseAll() 및 HID Button Release 수행
```

### v0415 변경
- `_macroAbortToken++` + `active=false`가 `_lock()` 하 원자적 (재정렬 방지)
- `_engine.resetEmaState()` 호출 추가 (Phase 5 Q2-a)
- `_reloadActiveProfile` 내 `static ST_C10_ProfileConfig_t` (스택 2.2KB 절감)

### v0415 핵심 변경 — BB-1 공통 헬퍼 확장

**v0412 문제**: `_handleSlotButton`에만 sanitization 적용. `_handleGesture`(제스처)는 미적용 → Tilt Hold를 KB_REPEAT로 매핑 시 키 stuck.

**v0415 해결**: `_sanitizeMomentarySlot(slot)` namespace 정적 헬퍼로 통합:
- `MOUSE_HOLD` → `MOUSE_CLICK`
- `KB_REPEAT` → `KB_TAP`
- `CONSUMER_REPEAT` → `CONSUMER_TAP`
- `holdMode = EN_C20_HOLD_NONE` 강제

**적용 위치**:
- `_handleSlotButton` — 버튼 순간 이벤트(CLICK/DOUBLE/LONG)
- `_handleGesture` — 제스처 발동 (Flick/Linear/Tilt)

### Side C 이벤트 처리 (v0415)

| 이벤트 | 하드코딩 | 슬롯 매핑 |
|---|:---:|:---:|
| CLICK | – | ✓ (S11) |
| DOUBLE | ✓ (Mode Cycle) | – |
| LONG | **명시적 무시** (v0415) | – |
| HOLD_2S | ✓ (Pairing) | – |
| HOLD_3S | ✓ (Host Cycle + exitPairing) | – |

### Side F 이벤트 처리

| 이벤트 | 하드코딩 | 슬롯 매핑 |
|---|:---:|:---:|
| DOWN | ✓ (`_frontHoldActive = true` + return true) | – |
| UP | ✓ (`_frontHoldActive = false` + return true) | – |
| CLICK | – | ✓ (S9) |
| LONG | – | ✓ (S10) |

### 매크로 대체(Replace) 정책
- 이미 매크로가 실행 중일 때 `_startMacro(newIdx)` 호출 시 **abort 토큰 증가 없이 조용히 대체** (v0412 정책 유지)
- `switchProfile`/`_setActiveMode`/`forceReleaseButtons`/BLE disconnect/SafeMode 진입 시에는 반대로 `_lock()` 하 `_macroAbortToken++`로 명시적 abort

## 4. HID 커맨드 큐 처리 흐름 (commTask)

`_qHidCmd`를 통해 웹 태스크 및 내부 요청이 HID 실행을 위임하는 경로입니다. **오직 commTask만 `_mouse`/`_keyboard` 인스턴스를 제어**한다.

```mermaid

    Enq --> QHid["_qHidCmd size=4"]
    QHid -- "Full" --> Fallback["RELEASE_ALL이면 _reqCommReleaseAll = true"]
    QHid -- "OK" --> Comm["commTask 매 루프"]
    Fallback --> Comm
    Comm --> GateCheck{"_reqCommReleaseAll?"}
    GateCheck -- "Yes" --> ForceRel["_actExec.releaseAll + _doReleaseAllButtons"]
    GateCheck -- "No" --> Discard{"QUEUE 비었나?"}
    ForceRel --> Discard
    Discard -- "비었음" --> Next["다음 처리: _qActionExec"]
    Discard -- "있음" --> CmdKind{"cmd 종류"}
    CmdKind -- "RELEASE_ALL" --> R1["_actExec.releaseAll + _doReleaseAllButtons"]
    CmdKind -- "TEST_PPT" --> R3["_sendPptKey2"]
    R1 --> Next
    R3 --> Next
```

### v0415 변경 — `ST_E10_HidCmd_t` 구조 축소
- `holdMs` 필드 삭제 (TEST_CLICK 삭제(rev5) 이후 Dead)

### commTask Gate 진입 시퀀스 (SafeMode / OTA Guard)

게이트 진입 시 commTask는 다음 순서로 큐를 정리:

1. `_lock()` 하 `_macroAbortToken++` + `active=false` (v0415 원자화)
2. `_qHidCmd` 드레인 (모든 대기 cmd 폐기)
3. `_qActionExec` 드레인 (모든 대기 액션 폐기)
4. `_qFrame` 1회 receive (stale frame 폐기 — gate 해제 후 1회 커서 점프 방지)
5. 최초 1회만 `_actExec.releaseAll` + `_doForceReleaseNow`
6. 20ms 대기 후 continue

## 5. 매크로 실행 상태머신 흐름 (`_tickMacro`)

`commTask` 루프 내에서 프레임 지연 없이 스텝별 딜레이와 실행을 제어하는 비동기 상태머신입니다.

```mermaid
flowchart TD
    Tick["commTask 매 루프: _tickMacro"] --> Active{"_macroState.active?"}
    Active -- "false" --> End1["즉시 리턴"]
    Active -- "true" --> TokenCheck{"startToken == _macroAbortToken?"}
    TokenCheck -- "불일치" --> Abort["ABORTED: active=false + WARN 로그"]
    TokenCheck -- "일치" --> StepCheck{"stepIdx >= stepCount?"}
    StepCheck -- "초과/완료" --> End2["매크로 종료: active=false"]
    StepCheck -- "진행중" --> DelayCheck{"delayMs 경과?"}
    DelayCheck -- "미경과" --> Wait["논블로킹 대기: 리턴"]
    DelayCheck -- "경과" --> ExecStep["_actExec.exec step isDown=true"]
    ExecStep --> Advance["stepIdx++ / stepStartMs = now"]
    Advance --> Tick
```

### v0415 정책 명확화
- **"블로킹 없음"은 delay에 한정**. step 실행(`_actExec.exec`)은 HID tap 지속 (~28ms) 블로킹.
- 매크로 8 step × 28ms = 최대 224ms 누적 블로킹 (분산 실행).
- 커서 프레임 소비는 각 step 사이에 계속됨.

### `_startMacro` v0415 원자화

```
1. _lock()
2. prev active 검사 → WARN 로그 (replace)
3. profile valid + idx range 검증
4. _macroSnapshot = _cfgProfile.macros.macros[idx]
5. state 초기화 (macroIdx, stepIdx, stepStartMs, startToken)
6. _macroState.active = true   ← 마지막 write
7. _unlock()
```

### 취소 정책 (v0415 원자화)
- `_macroAbortToken` 카운터가 `_macroState.startToken`과 다르면 즉시 abort
- **`switchProfile`, `_setActiveMode`, `forceReleaseButtons`, BLE disconnect edge, SafeMode/OTA gate 진입** 시 `_lock()` 하 토큰 증가
- **`_startMacro(newIdx)` 자체는 토큰을 증가시키지 않음** (조용히 대체)

## 6. 전원 관리 흐름 (`sensorTask` 내부, v0415 Safe/Pairing 분기)

```mermaid
flowchart TD
    Loop["sensorTask 매 루프"] --> Defer["_powerNotifyPending 소비"]
    Defer --> Cond{"Sleep 조건 검사"}
    Cond -- "실패" --> Next["다음 프레임 진행"]
    Cond -- "성공" --> TimeoutCheck{"elapsed >= timeout?"}
    TimeoutCheck -- "미충족" --> Next
    TimeoutCheck -- "충족" --> DeepCheck{"deep_idle_timeout 초과?"}
    
    DeepCheck -- "예" --> DeepLEDSuspend["_led.suspend: blocking fadeout RED"]
    DeepLEDSuspend --> Deep["deepSleepNow now, hid, pairing, safe: MPU PWR_MGMT_1=0x40 write"]
    DeepCheck -- "아니오" --> LEDSuspend["_led.suspend: blocking fadeout RED"]
    LEDSuspend --> Sleep["sleepNow now, safeOrPairing"]
    
    Sleep --> Wake["Wake 이벤트: Safe=Side C / 일반=MPU+6버튼"]
    Wake --> LEDResume["_led.resume: async fadein base color"]
    LEDResume --> FastRecalib["_biasTracker.startFastRecalibrate fast_recalib_ms"]
    FastRecalib --> Notify["_onPowerWake: xTaskNotifyGive commTask"]
    Notify --> Next
```

### Deep Sleep 진입 전 전원 격리 시퀀스 (v0415 하드닝)
1. **WS2812 래칭 차단**: `deepSleepNow()` 호출 직전 `_led.suspend(v_snap)`를 선제 호출하여 LED를 완전 소등 (미호출 시 슬립 중 LED 전류 유지 버그 차단).
2. **MPU6050 센서 수면화**: `deepSleepNow()` 내부에서 `G_MPU_PWR1_SLEEP (0x40)` 비트를 I2C 레지스터 `0x6B`에 기입하여 센서를 저전력 수면 모드로 진입시킨 후 ESP32 deep sleep 실행.

### Sleep 조건 (모두 만족)
- `!isSafeMode() && !isOtaGuard()`
- `!_moveGateHeld && !_frontHoldActive`
- `_qActionExec` 비어있음 + 매크로 미실행
- 유휴 시간 >= Mode/BLE/Pairing별 timeout

### v0415 Safe/Pairing Wake Mask 분기

| 시나리오 | 사용 마스크 |
|---|---|
| Light-sleep 일반 | `buildWakeMaskNormal()` (MPU + 6버튼) |
| Light-sleep Safe | `buildWakeMaskSafe()` (Side C 단독) |
| Light-sleep Pairing | `buildWakeMaskSafe()` |
| Deep-sleep 일반 | `buildWakeMaskButtons()` (6버튼, MPU 제외) |
| Deep-sleep Safe | `buildWakeMaskSafe()` (Side C 단독) |
| Deep-sleep Pairing | (sleep 금지 — `p_pairing` 시 return false) |

### SLEEP_NOW 즉시 진입 (v0415 Q4-a)

```
_handleSpecial(SLEEP_NOW):
  1. _led.suspend(snap)  — blocking fadeout RED
  2. safeOrPairing = (_safeMode || _ble.isPairing())
  3. _power.sleepNow(now, safeOrPairing)  — wake까지 blocking
  4. _led.resume(snap)  — async fadein
  5. if (didSleep && _cfgProfileValid)
         _biasTracker.startFastRecalibrate(_cfgProfile.e10.power.fast_recalib_ms)
```

**주의**: `fast_recalib_ms`는 **E10 config 단독 SSOT** (P20 필드 삭제, Round E).

### v0415 OTA Guard 체크 최적화 (Round M)
- **`index==0`에서만 Guard 체크** (매 청크마다 `getStatus()` 호출 제거)

- `buildProfileJson`은 항상 `p_out["ver"] = G_C10_CFG_VER` (411)을 기록합니다.

## 11. MPU6050 I2C 진단, 주소 자동 감지 및 런타임 복구 흐름

부팅 초기화 실패 및 런타임 I2C 버스 멈춤(Lock-up)을 방지하는 자가 진단 및 다계층 복구 시퀀스입니다.

```mermaid
flowchart TD
    Start["MPU begin 실패 시: _diagAndRecoverMpu"] --> LineChk{"SDA/SCL 라인 레벨 검사"}
    LineChk -- "SDA 또는 SCL Low" --> Unlock["9-펄스 SCL 토글 + STOP 조건 생성"]
    LineChk -- "Both High 정상" --> WireInit["Wire.begin 100kHz 저속 복구 모드"]
    Unlock --> WireInit
    WireInit --> Scan["3-Round I2C 스캔: 0x68 및 0x69 프로브"]
    Scan --> ProbeResult{"응답 감지?"}
    ProbeResult -- "실패" --> LogFail["진단 가이드 로그 출력 + false"]
    ProbeResult -- "감지" --> WhoAmI{"WHO_AM_I 0x75 레지스터 == 0x68?"}
    WhoAmI -- "불일치" --> Warn["경고 로그 + 감지 주소 임시 채택"]
    WhoAmI -- "일치" --> SetAddr["_mpuAddr 할당 0x68 또는 0x69"]
    Warn --> SetAddr
    SetAddr --> SyncPwr["_power.setMpuAddr _mpuAddr 동기화"]
    SyncPwr --> MpuReinit["_mpu.begin _mpuAddr 재초기화 성공 true"]
```

### 1) 부팅 진단 및 버스 언락 (`_diagAndRecoverMpu`)
1. **GPIO 레벨 점검**: GP4(SDA), GP5(SCL) 핀의 디지털 입력 레벨을 측정하여 버스 라인이 Low로 붙어있는지 확인.
2. **9-Pulse Bus Unlock**: 슬레이브가 ACK 상태에서 정지하여 SDA를 Low로 잡고 있는 경우, SCL을 9회 수동 토글한 후 STOP(SDA High) 조건을 만들어 I2C 상태머신을 리셋.
3. **100kHz 저속 스캔**: 노이즈 마진 확보를 위해 100kHz 클럭으로 3회 라운드 스캔 수행.
4. **WHO_AM_I 검증 및 주소 바인딩**: 0x68 또는 0x69 주소에서 0x75 레지스터를 조회하여 MPU6050 정상 응답을 검증하고, `_mpuAddr` 및 `_power.setMpuAddr`에 동기화.

### 2) 런타임 선제 점검 (sensorTask Pre-probe)
- `sensorTask` 루프에서 `_mpu.getEvent()` 호출 전, 경량 I2C 송신 프로브(`Wire.beginTransmission(_mpuAddr)` / `endTransmission()`)를 수행하여 통신 실패를 선제 감지.
- **카운터 분리 (v0415 하드닝)**: 선제 프로브 실패는 `_consecutiveI2cFail`로 독립 계측(10회 연속 실패 시 복구), 센서 메인 틱 루프 실패는 `_consecutiveFailures` 및 `_errMpuComm`으로 계측하여 진단 간섭 방지.
- 연속 10회 실패(`_consecutiveI2cFail >= 10`) 시 `_recoverI2C()`를 트리거하여 비차단 방식으로 복구 수행.

### 3) 슬립 복귀 복원 (P20 Wake)
- Light-sleep 복귀 시 `Wire.end()` / `Wire.begin()` 후 `_restoreMpuAfterWake(true)`를 호출하여 MPU6050 내부 전원 관리 레지스터(PWR_MGMT_1) 및 인터럽트 레지스터를 즉시 정상 상태로 복구.

## 13. D10 Logger 2단계 락(Two-Phase Locking) 및 Serial 단일 버퍼 파이프라인

모든 태스크(`sensorTask`, `commTask`, `webTask`, `ledTask`)에서 호출되는 `CL_D10_Logger`의 spinlock 경합을 수십 나노초로 최소화하고, Serial 포트 출력 인터리빙이 FreeRTOS 링버퍼 임계구역에 간섭하지 않도록 분리한 파이프라인입니다.

```mermaid
flowchart TD
    LogReq["로그 호출: log/info/warn/err"] --> LevelCheck{"로그 레벨 필터 통과?"}
    LevelCheck -- "No" --> Ret1["즉시 리턴"]
    LevelCheck -- "Yes" --> TimeSnap["millis 단일 타임스탬프 취득"]
    TimeSnap --> Fmt["vsnprintf: 스택 로컬 버퍼 96바이트 포맷팅"]
    Fmt --> CritEnter["Phase 1: portENTER_CRITICAL(&s_mux)"]
    CritEnter --> SlotCalc["v_idx 슬롯 인덱스 계산"]
    SlotCalc --> OverwriteCheck{"버퍼 Full 여부?"}
    OverwriteCheck -- "Yes Full" --> BumpHead["s_head 전진 + s_overwriteCount++"]
    OverwriteCheck -- "No 여유" --> BumpCount["s_count++"]
    BumpHead --> CritExit["portEXIT_CRITICAL(&s_mux)"]
    BumpCount --> CritExit
    
    CritExit --> PushPayload["Phase 2 Lock-Free: s_buffer[v_idx] 메시지 복사"]
    PushPayload --> TruncCheck{"96바이트 초과 잘림?"}
    TruncCheck -- "Yes" --> MarkTrunc["말미 ... 처리 + s_truncCount++"]
    TruncCheck -- "No" --> NullTerm["문자열 NUL 종료"]
    MarkTrunc --> SerialPrep["Serial 출력 준비"]
    NullTerm --> SerialPrep
    
    SerialPrep --> SingleWrite["256바이트 스택 버퍼 단일 조립 ➔ _serial➔write 1회"]
    SingleWrite --> Done["완료"]
```

### 핵심 규약
1. **Two-Phase Locking (임계구역 극소화)**: Phase 1에서 spinlock(`portENTER_CRITICAL`)으로 극단적으로 짧은 시간(수십 나노초) 동안 슬롯 인덱스(`v_idx`)만 원자적으로 확보/예약하고 즉시 critical을 해제. Phase 2에서 할당된 인덱스 슬롯에 critical 외부에서 락 없이 안전하게 96바이트 페이로드를 복사. 각 태스크는 서로 다른 인덱스를 가지므로 무경합.
2. **Serial 인터리빙 방지 (단일 버퍼 Write)**: `printf` 다중 호출을 금지하고 라인 전체를 256바이트 스택 버퍼에 사전 조립하여 `_serial->write(buf, len)`을 1회만 호출함으로써 USB CDC 패킷 분할 인터리빙을 원천 차단.
3. **USB CDC 초기화 대기 동기화**: `main.cpp` 부팅 시 `Serial`이 열릴 때까지 최대 1500ms 동안만 조건부 대기 루프를 두어 초반 부팅 로그 유실 차단.

```mermaid
flowchart TD
    ReqSave["C10 설정 저장 요청: _saveIndex 또는 _saveBootState"] --> PreEnsure["디렉토리 보장 여부 캐시 확인: _dirsEnsured"]
    PreEnsure --> TmpWrite["임시 파일 tmp_path에 신규 JSON 기록 및 flush"]
    TmpWrite --> VrfTmp{"임시 파일 크기 및 무결성 검증?"}
    VrfTmp -- "실패" --> DelTmp["tmp_path 삭제 후 에러 반환"]
    VrfTmp -- "성공" --> OldRot["기존 main_path ➔ old_path 로 rename 백업"]
    OldRot --> MainRot["신규 tmp_path ➔ main_path 로 rename 승격"]
    MainRot --> RotCheck{"main 승격 성공?"}
    RotCheck -- "예 성공" --> DelOld["백업 old_path 파일 정리 및 완료"]
    RotCheck -- "아니오 실패" --> Rollback["롤백: old_path ➔ main_path 복구"]
    Rollback --> FailRet["에러 반환: 원본 데이터 보존"]
```

### 핵심 규약
1. **임시 파일 선행 검증 (Write-then-Validate)**: 임시 파일 작성이 완전히 성공하고 파일 크기가 유효할 때만 회전을 시작.
2. **2단계 Rename 원자성 회전**: `main -> old`, `tmp -> main` 순서로 안전하게 파일 전환.
3. **실패 시 자동 롤백**: `tmp -> main` 실패 시 즉시 `old -> main`으로 복구하여 파일 손상 방지.
4. **`_bootMutex` 전역 동기화**: `boot.json` 읽기/쓰기/SafeMode 클리어 시 다중 태스크 경합 방지를 위해 전용 뮤텍스 보호.

## 15. LED 태스크 스택 관측 파이프라인 (rev13 신규, B-2)

`_ledTask`(50ms) → 매 tick 후 워터마크 샘플 → `_stackLedMinWords`(단조 최소) 갱신 → `getStatus()` 노출 → `/api/status` 응답 → 프론트 관측 카드.

```mermaid
flowchart TD
    Tick["_ledTask 매 50ms"] --> Neo["_led.tick: WS2812 상태머신"]
    Neo --> HW["uxTaskGetStackHighWaterMark nullptr"]
    HW --> Cmp{"v_hw < _stackLedMinWords?"}
    Cmp -- "Yes 또는 초기 0" --> Update["_stackLedMinWords = v_hw"]
    Cmp -- "No" --> Keep["유지"]
    Update --> Sleep["vTaskDelayUntil pdMS_TO_TICKS 50"]
    Keep --> Sleep
    Sleep -. "비동기 관측 (webTask)" .-> Get["getStatus: p_out.task_stack_led_min_words = _stackLedMinWords"]
    Get --> Api["/api/status groups.e10.obs.task_stack_led_min_words"]
    Api --> UI["프론트 관측 표시"]
```

### 핵심 규약:
1. **단조 최소(Monotonic Minimum) 갱신**: `sensorTask`/`commTask`와 동일 패턴 적용 (초기 0 센티넬 처리).
2. **비차단 초경량 관측**: 50ms 주기 종료 시 호출되며, 오버헤드는 수 μs 수준으로 주기 예산에 영향 없음.
3. **문서-코드 정합**: SPEC·BUDGET·STATE·FLOW 4대 문서 및 진단 구조체에서 동일 필드명(`task_stack_led_min_words`) 일관 사용.
