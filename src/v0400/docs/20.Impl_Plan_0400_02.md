

# 웹 기반 사용자 개별화 고도화 — 통합 설계 검토

## 0. 요구사항 정리

| 축 | 확정 사항 |
|---|---|
| **A. 프로파일 세트** | 다중 설정 (사용자/상황별) |
| **B. 매크로** | 액션 시퀀스 (다단 실행) |
| **D1. 자유도** | Option 1(slot중심) + 2(action중심) + 3(macro editor) 모두 |
| **D2. 트리거 라이브러리** | Tier A(기존 27) + 재검토 |
| **D3. 구조** | Global + Mode별 Override |
| **D4. 잠금** | S1/S5/S12/S13 유지 |
| **D5. Test** | Live Test |
| **D6. 마이그레이션** | 없음 (v0320 config 폐기) |

**핵심 난제:** 프로파일 × Global+Override × 매크로 × 3 UI view가 **동일 데이터의 다른 표현**이 되어야 함.

## 1. 아키텍처 결정 4개

### 1-1. 데이터 계층 (3층)

```
[Profile Layer]          5개 (Office / Gaming / Present / TV / Spare)
   │
   ├─ [Global Slots]     27 트리거 × Action  (모든 Mode 공통)
   │
   ├─ [Mode Overrides]   Mode별 예외 (override_mask로 표시)
   │
   ├─ [Macro Library]    Profile별 매크로 (최대 8개)
   │
   └─ [E10 Params]       DPI/감도/임계/Front Hold 등
```

**결정:** 프로파일이 완전한 설정 단위. 프로파일 전환 = 모든 것 스왑.

### 1-2. Global + Override 표현 (D3-B)

**문제:** Mode 3개 × 트리거 27개 × Action = 81슬롯. 그런데 대부분 Mode 공통.

**해결:** Global + Bitmask Override

```c
struct ST_C20_ProfileSlots_t {
    ST_C20_ActionSlot_t global[27];        // 모든 Mode 공통 (27 × 8 = 216B)
    ST_C20_ActionSlot_t modes[3][27];      // Mode별 override (216 × 3 = 648B, 실제 사용분만)
    uint32_t overrideMask[3];              // [mode] 각 27bit (or 32bit) — 12B
};  // ~880B
```

**규칙:**
```
slot(mode, trig) =
   if (overrideMask[mode] & (1 << trig))
       modes[mode][trig]
   else
       global[trig]
```

**잠금 트리거(S1/S5/S12/S13):** `global` 및 `modes[]`에 저장은 되나 UI에서 편집 불가.

### 1-3. 매크로 자료구조 (B)

```c
#define MAX_MACRO_STEPS   8
#define MAX_MACROS        8

struct ST_C20_MacroStep_t {
    uint8_t  kind;       // 1~9 (primitive만. 10=MACRO 금지: 중첩 방지)
    uint8_t  holdMode;   // 0=NONE, 1=PRESS (홀드 지속), 2=REPEAT
    uint16_t delayMs;    // 실행 전 대기 (0~2000)
    uint16_t param16;
    uint16_t _pad;
    uint32_t param32;
};  // 16 bytes

struct ST_C20_Macro_t {
    char     name[16];                       // 사용자 지정
    uint8_t  stepCount;                      // 1~8
    uint8_t  _pad[3];
    ST_C20_MacroStep_t steps[MAX_MACRO_STEPS];
};  // 16 + 4 + 128 = 148 → align 148

struct ST_C20_MacroLib_t {
    uint8_t  count;                          // 0~8
    uint8_t  _pad[3];
    ST_C20_Macro_t macros[MAX_MACROS];
};  // 4 + 8×148 = 1188B ≈ 1.2KB
```

**매크로 실행:**
```
1. commTask가 slot.kind == MACRO 받음
2. param32 = macro index
3. macro의 step 순회:
   - delayMs 대기
   - step 실행 (primitive)
   - repeat/hold 처리
4. 시퀀스 완료
```

**매크로 중 취소:** 진행 중 ForceRelease 또는 Mode 전환 시 abort flag.

### 1-4. Action 표현 확장

**기존 `ST_C20_ActionSlot_t` (8B) 유지 + kind 확장:**

```c
enum EN_C20_ActionKind_t : uint8_t {
    EN_C20_ACT_NONE            = 0,
    EN_C20_ACT_MOUSE_CLICK     = 1,
    EN_C20_ACT_MOUSE_HOLD      = 2,
    EN_C20_ACT_MOUSE_WHEEL     = 3,
    EN_C20_ACT_KB_TAP          = 4,
    EN_C20_ACT_KB_COMBO        = 5,
    EN_C20_ACT_KB_REPEAT       = 6,
    EN_C20_ACT_CONSUMER_TAP    = 7,
    EN_C20_ACT_CONSUMER_REPEAT = 8,
    EN_C20_ACT_SPECIAL         = 9,
    EN_C20_ACT_MACRO           = 10,   // 신규: param32 = macro index

```

**변경 없음.** `param32`가 macro index로 해석될 뿐. 하위호환 + 크기 동일.

## 4. Global + Override 메커니즘

### 4-1. 저장 최적화

**Override 최소화 원칙:**
- Global에 모든 값 저장 (default)
- Mode별 차이만 override
- `override_mask`로 표시

**예시:**
```
Global: S9 = Volume Up (모든 Mode)
Mode 2: S9 = PageDown (PPT 전용)
→ global[9] = Volume Up
→ override_mask[1] |= (1<<9)
→ modes[1].slots[9] = PageDown
```

### 4-2. 런타임 조회

```c
ST_C20_ActionSlot_t _resolveSlot(uint8_t p_mode, uint8_t p_trig) {
    const uint8_t m = p_mode - 1;   // 1~3 → 0~2
    if (_profile.overrideMask[m] & (1u << p_trig)) {
        return _profile.modes[m].slots[p_trig];
    }
    return _profile.global[p_trig];
}
```

**O(1).** 조회 부담 없음.

### 4-3. UI 표시

```
┌────────────────────────────────────────────┐
│ Mode 1 (PC) 편집 중  [Global 상속 표시]     │
├────────────────────────────────────────────┤
│ S1  🔒 Top L Click → Mouse L Hold (잠금)   │
│ S2  [G] Top L Double → Alt+Tab             │
│ S3  [G] Top L Long → (없음)                │
│ ...                                        │
│ S9  [M1] Side F Click → Volume Up ← 오버라이드 │
│ ...                                        │
└────────────────────────────────────────────┘

[G] = Global 상속
[M1] = Mode 1 오버라이드
```

**토글:** "Global로 되돌리기" 버튼 → override 삭제.

## 5. 실행 흐름

### 5-1. sensorTask (버튼/제스처)

```
_onBtnEvent / _handleGesture
  ↓
_resolveSlot(_activeMode, trigger)
  ↓
if (kind == SPECIAL):
    _handleSpecial() 즉시 (sensorTask)
else if (kind == MACRO):
    _enqueueAction(slot, isDown)   // commTask가 매크로 시퀀서 실행
else:
    _enqueueAction(slot, isDown)
```

### 5-2. commTask (Action 실행)

```
_qActionExec drain
  ↓
_actExec.exec(slot, isDown)
  ↓
if (kind == MACRO):
    _runMacro(macroIndex)    // 신규
else:
    (기존 실행)
```

**`_runMacro` (신규):**
```cpp
void _runMacro(uint8_t p_macroIdx) {
    if (p_macroIdx >= _macroLib.count) return;
    const ST_C20_Macro_t& m = _macroLib.macros[p_macroIdx];

    _macroAbort = false;

    for (uint8_t i = 0; i < m.stepCount; i++) {
        if (_macroAbort) break;

        const ST_C20_MacroStep_t& s = m.steps[i];
        if (s.delayMs > 0) {
            // abort 가능한 delay
            const uint32_t t0 = millis();
            while ((millis() - t0) < s.delayMs) {
                if (_macroAbort) break;
                vTaskDelay(pdMS_TO_TICKS(10));
            }
        }

        // primitive 실행 (SPECIAL 제외)
        ST_C20_ActionSlot_t slot = {s.kind, s.holdMode, s.param16, s.param32};
        _execPrimitive(slot, true);
    }
}
```

**주의:** 매크로 중 `Mode 전환`, `ForceRelease`, BLE disconnect → `_macroAbort = true`.

### 5-3. Profile 전환

```
1. 진행 중 액션/repeat 해제 (`_actExec.releaseAll()`)
2. 매크로 abort (`_macroAbort = true`)
3. 디스패처/제스처 리셋
4. ForceRelease
5. 신규 프로파일 로드 (LittleFS)
6. `_applyE10ToRuntime`
7. LED: 흰색 3회 flash
8. active_profile.json 저장
```

## 6. Web UI 3-View 설계

### 6-1. View 1 — Slot-centric (기존 Mode Slots 탭 확장)

**레이아웃:**
```
[Profile: Office ▼]  [Mode: 1 | 2 | 3]  [Global 보기]

┌────────────────────────────────────────────┐
│ 트리거              │ Action                 │
├────────────────────────────────────────────┤
│ S1  🔒 Top L Click  │ [Mouse L Hold    ] 🔒 │
│ S2    Top L Double  │ [Alt+Tab         ▼] [G]│
│ S3    Top L Long    │ [없음            ▼] [G]│
│ ...                                        │
│ S9  [M1] Side F Click│ [Volume Up      ▼] [M1]│
└────────────────────────────────────────────┘
```

**기능:**
- Action select: 프리셋 + 매크로 + NONE
- [G]/[M1] 배지: Global vs Override
- 우클릭 or 버튼: "Global로 되돌리기"
- 잠금 트리거: 회색 + 자물쇠

### 6-2. View 2 — Action-centric (신규 탭 "Action Map")

**레이아웃:**
```
[Action 검색: ____]

┌────────────────────────────────────────────┐
│ Action             │ 할당된 트리거           │
├────────────────────────────────────────────┤
│ Mouse L Hold       │ S1 (Global, 잠금)      │
│ Mouse R Click      │ S6 (Global)            │
│ Alt+Tab            │ S2 (Global)            │
│ PageDown           │ S1 (Mode 2 override)   │
│ Volume Up          │ S9 (Global)            │
│ 매크로: Ctrl+C→V   │ 없음                   │
│ ...                                        │
└────────────────────────────────────────────┘
```

**기능:**
- 각 액션 옆 [재할당] 버튼 → 트리거 선택 다이얼로그
- 액션 검색/필터
- 미할당 매크로 강조

### 6-3. View 3 — Macro Editor (신규 탭 "Macros")

**레이아웃:**
```
[매크로 목록]
  • Ctrl+C → V
  • Alt+Tab x2
  • Win+D → Wait → Win+D
  [+ 새 매크로]

[편집: Ctrl+C → V]
  Step 1: [KB Tap ▼] [LCtrl ▼] [C ▼]  delay: 0 ms    [×]
  Step 2: [KB Tap ▼] [LCtrl ▼] [V ▼]  delay: 100 ms  [×]
  [+ Step 추가]

  이름: [Ctrl+C → V]
  [저장] [삭제] [Live Test]
```

**기능:**
- Step 추가/삭제/순서 변경
- 각 Step별 kind 선택 → 파라미터 UI (기존 슬롯 편집기 재사용)
- Live Test: 매크로 즉시 실행 (BLE 연결 시)

### 6-4. 공통 UI 요소

- **Profile 관리 바** (모든 탭 상단):
  ```
  Profile: [Office ▼] [전환] [복제] [이름변경] [삭제]
  ```
- **Live Test 버튼** (Action/Macro 편집 시):
  - `POST /api/action/test {kind, p16, p32, holdMs}` → HID 전송
  - 매크로는 `{steps: [...]}` 형태

## 8. 검증/안전장치

### 8-1. 트리거 잠금

```c
static constexpr bool G_TRIG_LOCKED[27] = {
    true,  false, false, false, true,   // S1, S5
    false, false, false, false, false,
    false, true,  true,  false, false,  // S12, S13
    false, false, false, false,
    false, false, false, false,
    false, false, false, false
};
```

**서버 검증:** 잠금 트리거 편집 시도 → reject.
**클라이언트:** UI에서 disabled.

### 8-2. 매크로 검증

- Step 0~7 (최대 8)
- 각 Step kind 1~9 (MACRO 제외 — 중첩 방지)
- `delayMs` 0~2000
- 이름 16자
- 매크로 개수 0~8

### 8-3. 슬롯 검증

- Action kind 0~10
- MACRO 참조 시 index < `macroLib.count`
- 기타 기존 규칙 유지

### 8-4. 프로파일 검증

- 개수 1~5
- 이름 16자
- 각 프로파일 저장 시 `validateProfile()`
- 활성 프로파일 존재 보장

### 8-5. Cross-cutting

- 프로파일 전환 중 저장 시도 → 거부 (진행 중 플래그)
- 매크로 실행 중 편집 → 다음 실행부터 반영

## 9. 마이그레이션 정책 (D6)

**v0320 config (`config_0400.json`) 폐기.**

**부팅 시 동작:**
1. `/json/profiles/` 디렉토리 없음 → 새 구조로 초기화
2. `profile_0.json` 없음 → `makeDefaultsProfile(0)` 저장
3. `active_profile.json` 없음 → `{active_index: 0, profile_count: 1}` 저장
4. 기존 `config_0400.json` 있으면 → **무시** (삭제 안 함, 참고용 보존)
5. 사용자가 원하면 FactoryReset으로 정리

**장점:** 마이그레이션 로직 불필요. 코드 단순.

## 10. 자원 예산

### 10-1. Flash / RAM

| 항목 | 예상 |
|---|---|
| 코드 추가 | ~15~20 KB (Flash) |
| 정적 RAM | ~3 KB (매크로 버퍼 등) |
| 힙 사용 | 프로파일 로드 시 순간 ~5 KB |

**현재 Flash 45% → 46~47% 예상.** 여유.

### 10-2. LittleFS

| 항목 | 크기 |
|---|---|
| boot_state | ~200B |
| active_profile | ~50B |
| profile × 5 | ~4KB × 5 = 20KB (worst) |

**총 ~20KB.** LittleFS 여유 1.5MB 대비 무시.

### 10-3. Config body

- Global slots 27개 JSON: ~1.5KB
- Mode overrides 3개: ~2KB (worst)
- Macros 8개: ~2KB
- E10 params: ~1KB
- **총 ~7KB** (worst). Body max 8192 유지 가능.

**전체 규모:** Phase 5 (Mode 시스템) × **2~3배**. 예상 5~8일 (1인).
