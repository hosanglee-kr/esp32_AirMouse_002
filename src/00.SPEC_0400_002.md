# Elite AirMouse S3 — v0400 기술 사양서

> ESP32-S3-Zero + MPU6050 기반 3-Mode Air Mouse 플랫폼
> BLE HID Composite (Mouse + Keyboard + Consumer) / WS2812 LED / Light-sleep WoM

**소스 버전 접미사: `_0400` 통일**
**문서 대상: 개발자, 유지보수자, AI 어시스턴트**
**최신 반영: Phase 1~10 + Front Hold 스크롤 + 그룹 C 후속 + B20 disconnect-only**

이 프로젝트를 수정하기 전 반드시 알아야 할 8가지:

1. **모듈 약어**: `A40`(공용 유틸), `B20`(BLE), `C10`(Config), `C20`(Action), `D10`(로거), `E10`(AirMouse), `L10`(LED), `M10`(모션엔진), `M20`(BiasTracker), `M30`(제스처), `P20`(전원), `W10`(웹서버). 접두사가 파일/클래스/심볼에 그대로 반영.
2. **명명 규칙**: 전역 상수 `G_`, 전역 변수 `g_`, 클래스 `CL_`, struct `ST_`, enum `EN_`, private `_`접두사, 로컬 `v_`, 파라미터 `p_`. **위반 시 리뷰 반려.**
3. **ArduinoJson v7 정책**: `JsonDocument` 단일 타입만. `containsKey`·`createNestedArray/Object` **금지**. `doc["a"]["b"].to<JsonObject>()` 패턴 사용.
4. **E10은 7파일 분할**: `.h` + `Core/Hid/Motion/Diag/Task/Action_0400.cpp`.
5. **태스크 & 상태 소유권**: sensorTask(Core 1)와 commTask(Core 0)가 큐로 통신. **웹 태스크는 HID 직접 접근 금지**. **Special 액션은 sensorTask 단독 실행** (commTask에서 실행 금지).
6. **Mode 시스템**: 1(PC) / 2(PPT) / 3(TV). Side C 더블클릭으로 순환. 각 Mode는 슬롯 매트릭스 (`slots[15]`, `flick[4]`, `linear[4]`, `tilt[4]`).
7. **Action Registry**: 슬롯 값은 `{k, h, p16, p32}` 4-tuple. `k`=kind, `h`=holdMode.
8. **리팩터 이력**: Phase 1~10 + Front Hold + B20 disconnect-only. 상세는 §리팩터 이력.

## 🎯 프로젝트 개요

ESP32-S3-Zero + MPU6050 기반 **자이로 전용 공간 포인팅 에어마우스**. BLE HID Composite로 호스트(PC/macOS/Linux/Android TV/iOS)에 연결되며, 웹 UI로 실시간 커스터마이징을 제공.

### 핵심 특징

- **3-Mode 시스템**: PC / Presentation / Smart TV — 상황별 슬롯 매트릭스
- **자이로 전용**: 상보 필터 + 시그모이드 가속 + 적응형 LPF + Zero Snap
- **제스처 3계층**: Flick (P2P) / Linear (임펄스) / Tilt Hold (자세 유지)
- **Front Hold 스크롤**: Side F 누름 중 커서 감쇠 + 수직 휠 + 수평 팬
- **Action Registry**: ~40종 액션, 사용자 자유 배정
- **Zero-rate Bias Tracking**: 드리프트 자동 흡수
- **SafeBoot / OTA Guard**: 브릭 방지
- **WS2812 LED**: Mode 색상 / Flash / Blink / Fadeout
- **Light-sleep + WoM**: 60초 idle → 절전, MPU/버튼 wake
- **Multi-Host**: 최대 3 peer bond, disconnect-only 재연결 (whitelist는 라이브러리 제약)
- **Atomic Config**: tmp + bak + rollback
- **AP Fallback**: STA 실패 시 자동 AP (브릭 방지)

## 🏗️ 아키텍처

### 태스크 모델

| Task | Core | Prio | 주기 | Stack | 역할 |
|---|---|---|---|---|---|
| `_sensorTask` | 1 | 3 | 8ms (125Hz) | 8192 | IMU 읽기, FSM, 제스처, 프레임/커맨드 생산, Special 액션 |
| `_commTask` | 0 | 2 | 7ms | 4096 | 큐 소비 → HID 전송, 액션 실행 |
| `_ledTask` | 0 | 1 | 50ms | 2048 | LED 상태머신 **단독** tick |
| `AsyncWebServer` | (ESP-IDF 내부) | - | 이벤트 | - | HTTP, E10 API는 enqueue만 |
| main loop | 0 | - | 200ms | - | grace 판정, tickConfigSave |

### 데이터 흐름 (반드시 준수)

```
sensorTask ──push──> _qFrame (size=1, overwrite) ──recv──> commTask ──> HID
     │                                                            ▲
     │ (관측용)                                                    │
     └──lock──> _state ──read──> getStatus() (웹)                 │
                                                                  │
sensorTask ──enqueue──> _qActionExec (size=8) ──recv─────────────┤
web/sensorTask ──enqueue──> _qHidCmd (size=4) ──recv─────────────┘

Special 액션: sensorTask에서 _handleSpecial() 직접 호출 (commTask 안 거침)
LED tick:    _ledTask(50ms) 단독
```

**절대 금지:**
- 웹 태스크가 `_mouse`/`_keyboard` 직접 호출 → 반드시 `_qHidCmd` 경유
- sensorTask가 HID 직접 호출 → 반드시 `_qActionExec` 경유
- commTask가 `_state` 접근 → `_qFrame`만 사용
- commTask가 `_handleSpecial()` 실행 → **sensorTask 단독**
- commTask가 `_led.tick()` 호출 → **_ledTask 단독**

### 상태 소유권

| 상태 | 소유자 | 접근 방식 |
|---|---|---|
| `_state` (ST_E10_State_t) | sensorTask (관측), web (setSafeMode 등) | `_lock()` 하에 read/write |
| `_qFrame` | sensorTask(write), commTask(read) | FreeRTOS queue (lock-free) |
| `_qActionExec` | sensorTask/web(write), commTask(read) | FreeRTOS queue (timeout=0) |
| `_qHidCmd` | web(write), commTask(read) | FreeRTOS queue (timeout=0) |
| `_cfgE10Runtime` (snapshot) | `_lock()` 하에만 | H-3 원자화 경로 |
| motion config | setter: lock, reader: loop 시작 스냅샷 | C-4 |
| `_errHist`, `_spikes` | `_pushErr/_pushSpike` (내부 lock) | C-2 |
| `_hid` (BleCompositeHID) | **commTask 단독** | (예외: `isConnected()` read) |
| `_mpu`, `Wire` | **sensorTask 단독** | recover도 sensorTask |
| `_gesture` | sensorTask 단독 | update만 |
| `_biasTracker` | sensorTask 단독 | update/correct만 |
| `_ble` | sensorTask (tick), web (pairing) | 락 없음 (원자적 필드) |
| `_power` | sensorTask 단독 | sleepNow는 sensorTask |
| `_led` | **_ledTask 단독** | setModeColor/flash 등은 어느 태스크에서나 (내부 상태머신만 _ledTask가 tick) |
| `_frontHoldActive` | sensorTask (Side F 이벤트), reader: sensorTask | volatile, 원자적 |
| `_moveGateHeld` | sensorTask (Top M 이벤트), reader: sensorTask | volatile, 원자적 |
| `_activeMode` | sensorTask (Mode 전환), web(set via apply) | volatile, 원자적 |

### Mutex 정책

- `_mutex`: **recursive mutex** (`xSemaphoreCreateRecursiveMutex`). 이유: `setSafeMode`/`setOtaGuard`가 락 보유 중 `_pushErr` 재진입.
- `_lock()` / `_unlock()`: RAII 아님. 모든 경로에서 짝 맞춤.
- `_qFrame` overwrite: 무조건 성공(size=1).
- `_qHidCmd` / `_qActionExec` enqueue: `timeout=0`. 웹 태스크 블로킹 금지.

### 태스크 간 Special 액션 라우팅

**핵심 규칙:** Special 액션(`EN_C20_ACT_SPECIAL`)은 **sensorTask에서만 실행**.

```
_handleSlotButton / _handleGesture
  ├─ kind == SPECIAL → _handleSpecial() 직접 호출 (sensorTask 컨텍스트)
  └─ kind != SPECIAL → _enqueueAction() → commTask
```

**이유:** `_handleSpecial`이 `_ble`, `_led`, `_activeMode`, `_btnDisp`, `_gesture` 등 여러 리소스를 만짐. commTask에서 실행하면 sensorTask의 `_ble.tick()`, `_btnDisp.update()`와 경합.

`CL_C20_ActionExec::exec()`의 `EN_C20_ACT_SPECIAL` case는 안전망으로 무시(drop).

## 🔌 하드웨어

### 물리 배치

```
      [Top 면]
   [L] [M] [R]      ← 앞쪽 3버튼
   
   ┌─────────────┐
[F]│             │
```

### GPIO 배정

| 기능 | GPIO | RTC | Wake | 비고 |
|---|---|---|---|---|
| I2C SDA | 4 | ✓ | - | MPU6050 |
| I2C SCL | 5 | ✓ | - | MPU6050 |
| MPU INT1 | 6 | ✓ | WoM | Motion Detection |
| Top L | 12 | ✓ | EXT1 | Mouse L Hold |
| Side C | 13 | ✓ | EXT1 | Mode Cycle / Pairing / Host Cycle |
| Side F | 14 | ✓ | EXT1 | Front Hold (스크롤) / CLICK / LONG |
| Top R | 15 | ✓ | EXT1 | Mouse R |
| Top M | 16 | ✓ | EXT1 | Move Gate |
| Side R | 7 | ✓ | EXT1 | Rear |
| WS2812 DIN | 21 | ✗ | - | 단일 LED |
| Battery ADC | 1 | ✗ | - | (미구현) |

### MPU6050 설정

- Gyro Range: 250°/s
- Accel Range: 2G
- DLPF: 21Hz
- I2C: 400kHz
- INT: open-drain, active-low, latch

### 좌표계 규약 (필수)

| 물리 축 | 사용자 용어 | 용도 |
|---|---|---|
| gx | **Roll** (긴 축) | 커서 Y, Linear U/D, Flick U/D, **Front Hold 수평 팬** |
| gy | **Pitch** (좌우 축) | 휠, Linear L/R, **Front Hold 수직 휠** |
| gz | **Yaw** (수직 축) | 커서 X, Flick L/R |

**상보 필터:**
```cpp
_roll  = 0.98*(_roll  + gy*dt) + 0.02*accelRoll   // atan2(ay, az)
_pitch = 0.98*(_pitch + gx*dt) + 0.02*accelPitch  // atan2(-ax, az)
```

## 🎛️ Mode 시스템

### 3 Modes

| Mode | 이름 | LED | 용도 |
|---|---|---|---|
| 1 | PC Air Mouse | Blue | PC 커서/클릭 |
| 2 | Presentation | Green | PPT 슬라이드/제스처 |
| 3 | Smart TV | Orange | TV D-Pad/미디어 |

### 전환 (고정)

| 트리거 | 동작 |
|---|---|
| Side C Double Click | Mode 1 → 2 → 3 → 1 순환 |
| Side C Long (2초) | Pairing Mode 진입 (LED blink) |
| Side C 3초 + Top L DOWN | Host Cycle (disconnect + 재광고) |

**Mode 전환 시:**
- `_actExec.releaseAll()` — 진행 중 홀드/repeat 해제
- `_btnDisp.resetAll()` — 클릭 대기 리셋
- `_gesture.reset()` — 제스처 상태 리셋
- `_frontHoldActive = false` — Front Hold 리셋
- `_ble.exitPairing()` — Pairing 중이면 취소
- FSM 리셋 (`_precSub = EN_PREC_OFF`)
- `forceReleaseButtons()` — HID 안전
- LED: 신규 Mode 색 + 흰색 500ms flash

### Mode별 슬롯 매트릭스

각 Mode는 4 그룹:
- `slots[15]` — 물리 버튼 (S1~S15)
- `flick[4]` — Flick (LEFT/RIGHT/UP/DOWN)
- `linear[4]` — Linear 4방향
- `tilt[4]` — Tilt Hold (Mode 3 전용)

### 슬롯 → 트리거 매핑

| 슬롯 | 트리거 | 분류 |
|---|---|---|
| S1 | Top L Click | 🔒 하드코딩 (Mouse Left Hold, config 무시) |
| S2 | Top L Double | 설정 |
| S3 | Top L Long | 설정 |
| S4 | Top M Click | 설정 (Mode 1/2. Mode 3은 하드코딩 Enter) |
| S5 | Top M Hold | 🔒 하드코딩 (Move Gate) |
| S6 | Top R Click | 설정 |
| S7 | Top R Double | 설정 |
| S8 | Top R Long | 설정 |
| S9 | Side F Click | 설정 |
| S10 | Side F Long | 설정 |
| S11 | Side C Click | 설정 |
| S12 | Side C Double | 🔒 하드코딩 (Mode Cycle) |
| S13 | Side C 2초 Hold | 🔒 하드코딩 (Pairing) |
| S14 | Side R Click | 설정 |
| S15 | Side R Long | 설정 |

### 하드코딩 규칙 (`_handleHardcodedButton`)

- **Top L**: DOWN → Mouse Hold press, UP → release, CLICK → 스킵(중복 방지)
- **Top M**: DOWN → `_moveGateHeld=true`, UP → false + (Mode 3이면 Enter), LONG 이상 → 무시
- **Side C**: DOUBLE → Mode Cycle, HOLD_2S → Pairing, HOLD_3S → **무시** (조합 트리거로 별도)
- **Side F**: DOWN → `_frontHoldActive=true`, UP → false (CLICK/LONG은 슬롯 매핑 위임)
- **Top L DOWN + Side C 3초 hold** → Host Cycle (SLOT_MAP 진입 전에 검사)

## 🎬 Action Registry

### Action Kind

| kind | 이름 | p16 | p32 |
|---|---|---|---|
| 0 | NONE | - | - |
| 1 | MOUSE_CLICK | mask | - |
| 2 | MOUSE_HOLD | mask | - |
| 3 | MOUSE_WHEEL | axis<<8 \| dir | - |
| 4 | KB_TAP | usage | modifier |
| 5 | KB_COMBO | - | mod\|u1\|u2\|u3 |
| 6 | KB_REPEAT | usage | modifier |
| 7 | CONSUMER_TAP | - | 32-bit mask |
| 8 | CONSUMER_REPEAT | - | 32-bit mask |
| 9 | SPECIAL | special | - |

### Special Action

| 값 | 이름 | 처리 |
|---|---|---|
| 0 | NONE | - |
| 1 | GYRO_RECALIB | `requestGyroCalibration()` |

## 🎮 제스처 시스템 (M30)

### Flick (Peak-to-Peak)

**알고리즘:**
- 200ms 슬라이딩 윈도우
- `p2p = peak_max - peak_min`
- `p2p > p2p_th` → 부호 판정 (`|peak_max| > |peak_min|`)
- 쿨다운 600ms

**축:**
- 좌/우: `gz` (Yaw)
- 상/하: `gx` (Roll) — **Middle Hold 해제 시만**

**파라미터:**
- `p2p_th = 400 deg/s`
- `window_ms = 200`
- `cooldown_ms = 600`

### Linear (임펄스 적분)

**알고리즘:**
- 중력 성분 제거: `a_lin = a_raw - R(roll,pitch) * g`
- `|a_lin| > linear_th` → 윈도우 적분
- 300ms 윈도우 종료 시 `|impulse| > impulse_th` → 지배축 + 부호 판정

**활성 조건:**
- **Middle Hold 중만**

**파라미터:**
- `th = 0.3 m/s²`
- `impulse_th = 0.5 m/s`
- `window_ms = 300`

### Tilt Hold

**알고리즘:**
- Roll/Pitch 자세 > `angle_deg` 유지
- `hold_ms` 유지 시 발동
- 반복 `repeat_hz` Hz

**활성 조건:**
- **Mode 3 + Middle Hold 해제 시만**

**파라미터:**
- `angle_deg = 15`
- `hold_ms = 300`
- `repeat_hz = 3`

## ⚙️ 물리 엔진 (M10)

### 상보 필터 (Roll + Pitch)

```cpp
_roll  = 0.98f * (_roll  + gy*dt*DEG_TO_RAD) + 0.02f * atan2f(ay, az)
```

### 시그모이드 가속

```cpp
dpiGain = 15 + dpi_level*7
```

### 적응형 LPF

```cpp
delta = sqrt(x² + y²)
alpha = (delta > 3.0) ? 0.50 : 0.12
lpfX = x*alpha + lpfX*(1-alpha)
```

### Zero Snap

```cpp
if (|out| < 0.6) out = 0
```

### Click-Lock (150ms)

- `hard_click_lock=true`: 완전 고정 (`outX=outY=0`)
- `hard_click_lock=false`: 95% 감쇠 (`*= 0.05`)

## 📡 BLE (B20)

### Pairing Mode

- 트리거: Side C 2초 hold
- 동작: `NimBLEAdvertising::stop/start`, bond 유지
- 타임아웃: 30초
- 연결 시 자동 종료
- LED: 현재 Mode 색 1Hz blink

### Bond 관리

- 최대 peer 3개 (`CONFIG_BT_NIMBLE_MAX_BONDS = 3`)
- NVS FIFO (오래된 것 자동 삭제)
- 조회: `NimBLEDevice::getNumBonds()`
- 삭제: `NimBLEDevice::deleteAllBonds()`

### Host Cycle (disconnect-only)

- 트리거: Side C 3초 hold + Top L DOWN
- 동작:
  1. `_activePeerIndex` 순환 (0→1→2→0)
  2. 모든 connection `disconnect()`
  3. `NimBLEAdvertising::stop()` → `delay(30)` → `start()` (재광고)
  4. 재연결 윈도우 10초 (`_whitelistActive = true`)
- 대상 peer 선택은 **OS 자동 재연결**에 위임
- LED: 흰색 500ms flash
- Config 저장: main loop `tickConfigSave()` (200ms)

**NimBLE-Arduino 2.5.1 제약:**
- whitelist 필터 API 미노출 (`setScanFilter` 2인자, `filterAcceptListAdd` 없음)
- `getBondedDevices()` 없음
- **disconnect-only 방식으로 단순화**

### Composite HID

| Report ID | 내용 |
|---|---|
| 1 | Mouse: 5버튼 + X/Y + Wheel + AC Pan |
| 2 | Keyboard: mod + 6KRO |
| 3 | Consumer: 16-bit usage |

**Appearance:** `0x03C0` (HID Generic)

### Light-sleep 조건

다음 **모두** 만족:
- `sleep_idle_timeout_ms` 경과 (기본 60초, `0` = 비활성)

### MPU6050 WoM 구성

```
PWR_MGMT_1 = 0x00    // sleep 해제
ACCEL_CFG = 0x01     // HPF 5Hz
MOT_THR = 25         // ~100mg
MOT_DUR = 4          // 4ms 연속
INT_CFG = 0xE0       // LATCH | OPEN_DRAIN | ACTIVE_LOW
INT_EN = 0x40        // MOT_EN
PWR_MGMT_1 = 0x20    // CYCLE
PWR_MGMT_2 = 0xC7    // LP_WAKE 5Hz, Gyro Standby
```

### Wake 소스 (EXT1, LOW active)

```

+ Side F (14) + Top R (15) + Top M (16)
```


## 🛡️ SafeBoot / OTA Guard

### Boot State

파일: `/json/boot_state_0400.json`

```json
{
  "safe_mode": false,
  "fail_count": 0,
  "pending": false,
  "boot_ms": 0,
  "last_reset_reason": 0
}
```

### 절차

1. `begin()` → boot state 로드
2. 이전 `pending=true` + bad reset reason → `fail_count++`
3. `fail_count >= 2` → `safe_mode=true`
4. 이번 부팅 `pending=true` 마킹
5. 정상 부팅 후 `bootMarkOkIfGracePassed(8500ms)` → `pending=false`
6. 실패 시 30초 백오프

### Bad Reset Reason

`PANIC` / `INT_WDT` / `TASK_WDT` / `WDT` / `BROWNOUT`

### SafeMode 정책

**허용 API:**
- `/api/status`, `/api/diag`, `/api/diag/clear`, `/api/keycodes`
- `/api/safeboot`, `/api/ota`, `/api/ota/status`
- `/api/factory_reset`, `/api/reboot`, `/api/reboot/check`
- `GET /api/config`, `/api/config/export`, `/api/export`
- `/api/config/rollback`

**차단 API:**
- `/api/config/save`, `/api/config/apply`, `/api/config/import`
- `/api/control`, `/api/ppt`, `/api/ppt/test`

**SafeMode 진입:**
- AP SSID에 `-SAFE` 접미사
- E10 `_safeMode=true` → HID 차단
- `rollbackFromBak` 자동 시도

### OTA Guard

- `/api/control {"cmd":"set_ota_guard","enable":true}` → HID 차단
- OTA 업로드 시 자동 감지 → `ota_guard_blocked`
- Stale 회수: `_otaStartedMs` 30초 경과 시 강제 해제

### WiFi 브릭 방지

**정책:** `mode=STA` + STA 연결 실패 시 **AP fallback**.

이유: 사용자가 실수로 STA 골라도 브릭 방지.

## 🗂️ 리팩터 이력

### Phase 1~4 (E10 크리티컬)
- **C-1**: sensorTask `_pushFrame` 누락 → HID 큐 활성화
- **C-2**: `_pushErr` 무보호 → recursive mutex
- **C-5**: 캘리브 블로킹 → 버튼 샘플링
- **C-3**: 웹 태스크 HID 접근 → `_qHidCmd`
- **C-4**: 공유 변수 락 → config 스냅샷
- **H-2**: forceRelease 통일
- **H-3**: setter RMW 원자화
- **H-4**: 웹 블로킹 제거
- **M-2**: `_recoverI2C` 락 통일
- **M-4**: 전용 에러코드

### Phase 5 (Mode + 슬롯 매트릭스)
- 3-Mode 시스템
- Action Registry
- 슬롯 매핑 테이블

### Phase 6-J (LED)
- WS2812 + `_ledTask`

### Phase 7 (제스처)
- M30 Flick P2P / Linear / Tilt Hold

### Phase 8 (Sleep)
- P20 Light-sleep + WoM (EXT1 wake)
- Wake 후 LED 복귀

### Phase 9~10 (BLE)
- Pairing Mode (Side C 2초)
- Host Cycle (Side C 3초 + Top L)
- **disconnect-only 재연결** (whitelist는 NimBLE 2.5.1 제약)

### Front Hold 스크롤
- Side F Hold → 커서 감쇠 + 수직 휠 + 수평 팬
- 모든 Mode 일관

### 그룹 C 후속
- Sleep 조건 강화 (Front Hold/Pairing/큐)
- Wake 후 LED 복귀
- STA 실패 → AP fallback

### 그룹 B (BLE 심화)
- Pairing → 실동작
- Host Cycle → 실제 재연결

## 🎯 프로젝트 철학

AirMouse Elite S3는 **상용급 입력 디바이스 아키텍처**입니다.

- 태스크/상태 소유권 명확
- 락 정책 일관 (recursive, 짝맞춤)
- Special 액션 sensorTask 단독 실행
- LED _ledTask 단독 tick
- 브릭 방지 (SafeBoot / Atomic Config / OTA Guard / AP fallback)
- 관측성 (RMS / 스택 / dt / 오류 이력)
- 정책 일관성 (SafeMode API 게이트, Action 큐 일원화)
