
# Elite AirMouse S3 — v0400 기술 사양서

> ESP32-S3-Zero + MPU6050 기반 3-Mode Air Mouse 플랫폼
> BLE HID Composite (Mouse + Keyboard + Consumer) / WS2812 LED / Light-sleep WoM

**소스 버전 접미사: `_0400` 통일**
**문서 대상: 개발자, 유지보수자, AI 어시스턴트**

## 📌 AI 어시스턴트용 컨텍스트 (Read First)

이 프로젝트를 수정하기 전 반드시 알아야 할 8가지:

1. **모듈 약어**: `A40`(공용 유틸), `B20`(BLE), `C10`(Config), `C20`(Action), `D10`(로거), `E10`(AirMouse), `L10`(LED), `M10`(모션엔진), `M20`(BiasTracker), `M30`(제스처), `P20`(전원), `W10`(웹서버). 접두사가 파일/클래스/심볼에 그대로 반영.
2. **명명 규칙**: 전역 상수 `G_`, 전역 변수 `g_`, 클래스 `CL_`, struct `ST_`, enum `EN_`, private `_`접두사, 로컬 `v_`, 파라미터 `p_`. **위반 시 리뷰 반려.**
3. **ArduinoJson v7 정책**: `JsonDocument` 단일 타입만. `containsKey`·`createNestedArray/Object` **금지**. `doc["a"]["b"].to<JsonObject>()` 패턴 사용.
4. **E10은 6개 파일로 분할**: `.h` + `Core/Hid/Motion/Diag/Task/Action_0400.cpp`.
5. **태스크 & 상태 소유권**: sensorTask(Core 1)와 commTask(Core 0)가 큐로 통신. **웹 태스크는 HID 직접 접근 금지**. 위반은 즉시 버그.
6. **Mode 시스템**: 1(PC) / 2(PPT) / 3(TV). Side C 더블클릭으로 순환. 각 Mode는 슬롯 매트릭스 (`slots[15]`, `flick[4]`, `linear[4]`, `tilt[4]`).
7. **Action Registry**: 슬롯 값은 `{k, h, p16, p32}` 4-tuple. `k`=kind, `h`=holdMode.
8. **리팩터 이력**: Phase 1~10 (E10 크리티컬 → HID 태스크 일원화 → 원자성 → 제스처 → LED → BLE → Sleep).

## 🎯 프로젝트 개요

ESP32-S3-Zero + MPU6050 기반 **자이로 전용 공간 포인팅 에어마우스**. BLE HID Composite로 호스트(PC/macOS/Linux/Android TV/iOS)에 연결되며, 웹 UI로 실시간 커스터마이징을 제공.

### 핵심 특징

- **3-Mode 시스템**: PC / Presentation / Smart TV — 상황별 슬롯 매트릭스
- **자이로 전용**: 상보 필터 + 시그모이드 가속 + 적응형 LPF + Zero Snap
- **제스처 3계층**: Flick (P2P) / Linear (임펄스) / Tilt Hold (자세 유지)
- **Action Registry**: ~40종 액션, 사용자 자유 배정
- **Zero-rate Bias Tracking**: 드리프트 자동 흡수
- **SafeBoot / OTA Guard**: 브릭 방지
- **WS2812 LED**: Mode 색상 / Flash / Blink / Fadeout
- **Light-sleep + WoM**: 60초 idle → 절전, MPU/버튼 wake
- **Multi-Host**: 최대 3 peer bond, index 순환 (실제 재연결은 유보)
- **Atomic Config**: tmp + bak + rollback

## 🏗️ 아키텍처

### 태스크 모델

| Task | Core | Prio | 주기 | Stack | 역할 |
|---|---|---|---|---|---|
| `_sensorTask` | 1 | 3 | 8ms (125Hz) | 8192 | IMU 읽기, FSM, 제스처, 프레임/커맨드 생산 |
| `_commTask` | 0 | 2 | 7ms | 4096 | 큐 소비 → HID 전송, 특수 커맨드 실행 |
| `AsyncWebServer` | (ESP-IDF 내부) | - | 이벤트 | - | HTTP, E10 API는 enqueue만 |
| main loop | 0 | - | 200ms | - | grace 판정, tickConfigSave |

### 데이터 흐름 (반드시 준수)

```

sensorTask ──push──> _qFrame (size=1, overwrite) ──recv──> commTask ──> HID
│                                                            ▲
│ (관측용)                                                    │
└──lock──> _state ──read──> getStatus() (웹)                 │
│
sensorTask ──enqueue──> _qActionExec (size=8) ──recv─────────────┤
web/sensorTask ──enqueue──> _qHidCmd (size=4) ──recv─────────────┘

```

**절대 금지:**
- 웹 태스크가 `_mouse`/`_keyboard` 직접 호출 → 반드시 `_qHidCmd` 경유
- sensorTask가 HID 직접 호출 → 반드시 `_qActionExec` 경유
- commTask가 `_state` 접근 → `_qFrame`만 사용

### 상태 소유권

| 상태 | 소유자 | 접근 방식 |
|---|---|---|
| `_state` (ST_E10_State_t) | sensorTask (관측), web (setSafeMode 등) | `_lock()` 하에 read/write |
| `_qFrame` | sensorTask(write), commTask(read) | FreeRTOS queue (lock-free) |
| `_qActionExec` | sensorTask/web(write), commTask(read) | FreeRTOS queue (timeout=0) |
| `_qHidCmd` | web(write), commTask(read) | FreeRTOS queue (timeout=0) |
| `_cfgE10Runtime` (snapshot) | `_lock()` 하에만 | H-3 원자화 경로 |
| motion config | setter: lock, reader: loop 시작 스냅샷 | C-4 |
| `_errHist`, `_spikes` | `_pushErr/_pushSpike` (내부 lock) | C-2 |
| `_hid` (BleCompositeHID) | **commTask 단독** | (예외: `isConnected()` read) |
| `_mpu`, `Wire` | **sensorTask 단독** | recover도 sensorTask |
| `_gesture` | sensorTask 단독 | update만 |
| `_biasTracker` | sensorTask 단독 | update/correct만 |
| `_ble` | sensorTask (tick), web (pairing) | 락 없음 (원자적 필드) |
| `_power` | sensorTask 단독 | sleepNow는 sensorTask |

### Mutex 정책

- `_mutex`: **recursive mutex** (`xSemaphoreCreateRecursiveMutex`). 이유: `setSafeMode`/`setOtaGuard`가 락 보유 중 `_pushErr` 재진입.
- `_lock()` / `_unlock()`: RAII 아님. 모든 경로에서 짝 맞춤.
- `_qFrame` overwrite: 무조건 성공(size=1).
- `_qHidCmd` / `_qActionExec` enqueue: `timeout=0`. 웹 태스크 블로킹 금지.

🎮 제스처 시스템 (M30)

Flick (Peak-to-Peak)

알고리즘:

- 200ms 슬라이딩 윈도우
- p2p = peak_max - peak_min
- p2p > p2p_th → 부호 판정 (|peak_max| > |peak_min|)
- 쿨다운 600ms

축:

- 좌/우: gz (Yaw)
- 상/하: gx (Roll) — Middle Hold 해제 시만

파라미터:

- p2p_th = 400 deg/s
- window_ms = 200
- cooldown_ms = 600

Linear (임펄스 적분)

알고리즘:

- 중력 성분 제거: a_lin = a_raw - R(roll,pitch) * g
- |a_lin| > linear_th → 윈도우 적분
- 300ms 윈도우 종료 시 |impulse| > impulse_th → 지배축 + 부호 판정

활성 조건:

- Middle Hold 중만 (D14)

파라미터:

- th = 0.3 m/s²
- impulse_th = 0.5 m/s
- window_ms = 300

Tilt Hold

알고리즘:

- Roll/Pitch 자세 > angle_deg 유지
- hold_ms 유지 시 발동
- 반복 repeat_hz Hz

활성 조건:

- Mode 3 + Middle Hold 해제 시만 (D23)

파라미터:

- angle_deg = 15
- hold_ms = 300
- repeat_hz = 3

⚙️ 물리 엔진 (M10)

상보 필터 (Roll + Pitch)

```cpp
_roll  = 0.98f * (_roll  + gy*dt*DEG_TO_RAD) + 0.02f * atan2f(ay, az)
_pitch = 0.98f * (_pitch + gx*dt*DEG_TO_RAD) + 0.02f * atan2f(-ax, az)
```

시그모이드 가속

```cpp
dpiGain = 15 + dpi_level*7
out = dpiGain / (1 + exp(-0.8*(|in| - 2.0)))
```

적응형 LPF

```cpp
delta = sqrt(x² + y²)
alpha = (delta > 3.0) ? 0.50 : 0.12
lpfX = x*alpha + lpfX*(1-alpha)
```

Zero Snap

```cpp
if (|out| < 0.6) out = 0
```

Click-Lock (150ms)

🛡️ SafeBoot / OTA Guard

Boot State

파일: /json/boot_state_0400.json

```Json
{
  "safe_mode": false,
  "fail_count": 0,
  "pending": false,
  "boot_ms": 0,
  "last_reset_reason": 0
}
```

절차

1. begin() → boot state 로드
2. 이전 pending=true + bad reset reason → fail_count++
3. fail_count >= 2 → safe_mode=true
4. 이번 부팅 pending=true 마킹
5. 정상 부팅 후 bootMarkOkIfGracePassed(8500ms) → pending=false
6. 실패 시 30초 백오프

PANIC / INT_WDT / TASK_WDT / WDT / BROWNOUT
